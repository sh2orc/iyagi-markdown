## 원문 보존 — 불변 조건(§4-2)

- 읽기(`md-core::io::read_doc`): 바이트 → BOM 제거 → UTF-8 검증 → `\n` 정규화.
  BOM·CRLF 여부는 `DocMeta`로 **기록만** 한다.
- 쓰기(`write_doc_atomic`): 버퍼 텍스트 + 메타로 재인코딩 → 임시 파일 → fsync → rename.
- 무수정 저장은 일어나지 않는다: `App.saveActive`가 `doc == savedText`면 no-op.
- 자동 검증 3종(vitest `src/preservation.test.ts`):
  (a) 무수정 저장 no-op, (b) 랜덤 편집 200회 역적용 → 원문 복원,
  (c) 모드 전환 왕복 시 내용·선택 불변. 이 실패는 릴리스 차단.
- **모든 기능이 이 원칙 위에서 동작한다**: 서식·표 편집·위키링크·이미지 크기·
  책갈피·스타일 — 전부 텍스트 편집이거나 SQLite 사이드카.

## 라이브 프리뷰(§4-1)

- 구문 트리(lezer-markdown + GFM + `$…$`/`$$…$$` + `[^각주]` + `[[위키링크]]` +
  `#태그` + `==하이라이트==`)는 **표시용 읽기 전용**.
- **청크 증분 렌더**: 문서를 ~4k자 청크로 나눠 각 청크를 정확히 한 번만 계산.
  커서 이동당 재계산 = 청크 1~2개(문서 크기와 무관한 상수 비용).
- 블록(표·수식·다이어그램·제목)은 커서 줄 기준 노출, 인라인(`**`·`` ` ``·링크·
  `$…$`)은 **스팬 단위**(±1자) 노출(Typora 모델).
- 빈 줄은 0.42배 높이로 축소.
- 위젯: Math(KaTeX)·Diagram(mermaid)·Table·Task·Image(폭 드래그)·HRule·
  Bullet(깊이별 글리프)·Highlight.

## 노트 체계

- **위키링크** `[[이름]]`: 구문 인식 → 라이브 프리뷰 링크색 → 클릭 이동 →
  대상 없으면 새 파일 생성. `[[이름|표시]]`, `[[이름#앵커]]` 지원.
- **자동완성**: `[[` 입력 시 워크스페이스 문서 목록 팝업(서브시퀀스 퍼지).
- **백링크**: 이 문서를 `[[참조]]`하는 문서들 — 상태 줄 "🔗 N" 클릭 → 패널.
- **태그** `#태그`: pill 표시 → 클릭 → 워크스페이스 태그 검색.
- **빠른 열기**(명령 팔레트에서 파일 퍼지 검색), **폴더 전체 검색**(⇧⌘F) +
  **모두 바꾸기**(원자적 저장·메타 보존) — 문서 내 검색은 대소문자·정규식·
  **단어 단위**([w]) 토글.
- **입력 보조**: 스마트 문장부호(“”·…·–, 코드·수식 안 제외) · 서식 복사
  (Format Painter ⌥⌘C/⌥⌘V) · 서식 없이 붙여넣기(⌥⌘⇧V) · 특수 문자 패널 ·
  링크/이미지 설명 편집 대화상자 · 표 삽입 크기 지정 · 각주 호버 미리보기.
- **버전 기록**: 저장 직전 상태를 스냅숏(30개·60초 간격) — diff 미리보기 후 복원.
- **메모(Word "메모")**: 줄 앵커 사이드카 — 우클릭 추가·앰버 바·호버 팝오버·
  패널(편집·해결·삭제)·DOCX 원생 메모(commentRange/comments.xml)로 내보내기.
- **캡션**: 그림(`![설명](src)`)·표(표 아래 `: 설명` — Pandoc 규약) — 편집기
  표시·4경로 내보내기·SEQ 필드·그림/표 목차(lof/lot).
- **검수 허브**: 끊긴 링크(수)·긴 문장(수·점선 표시 토글)·고아 이미지(삭제).
- **파일 관리**: 사이드바 우클릭 — 새 문서·이름 변경·복제·Finder 보기.
- **편집 보조**: 스마트 문장부호·서식 복사(⌥⌘C/V)·서식 없이 붙여넣기·
  표 셀 Tab(끝에서 새 행)·특수 문자 패널·링크/이미지 설명 편집·
  같은 단어 강조·문법 노출은 '선택이 덮을 때만'.
- **변경 추적(Word Track Changes)**: 베이스라인 사이드카 diff — 본문
  표시·상태 줄 +N−R·검토 패널(이동·↺ 되돌리기·모두 수락)·다음/이전 탐색.
- **개요 재배치·분할 편집**: 목차 패널 드래그로 섹션 이동, 참조 보기 ✎로
  두 문서 동시 편집(뷰·탭 라우팅).
- **클릭=편집 규칙**: 텍스트류는 렌더 유지·문법은 선택 덮음 시만 노출,
  표 셀·수식 블록·다이어그램·프런트매터는 클릭으로 원문 진입.
- **접기**: 제목·목록·코드펜스·인용 — 거터 화살표.
- **세션 연속성**: 탭·커서·창·폭·참조 보기·접힌 폴더·찾기 상태·내보내기 옵션.

## 내보내기(§4-3/§4-4)

### HTML(프런트 `src/export/html.ts`)
markdown-it + KaTeX + highlight.js + mermaid(인라인 `<svg>`) + 각주.
이미지 data URI, KaTeX CSS+폰트 인라인, DOMPurify sanitize.
문서별 스타일(폰트·크기·행간·정렬·들여쓰기·강조색) 반영.

### PDF(src-tauri/src/pdf.rs)
CSS 다단 컬럼 페이지네이션(`column-gap = 2×여백`) → createPDF로 넓은
한 페이지 → CoreGraphics로 슬라이스. 전부 벡터. 페이지 번호(N / M) 옵션.

### DOCX(crates/md-export)
comrak AST → OOXML 직접 작성. Word 기본 스타일(제목·번호·표·하이퍼링크) +
문서별 스타일(폰트·크기·행간·정렬·들여쓰기·강조색).
- **SVG→DrawingML**(custGeom·그룹·편집 가능 텍스트 상자·화살표).
- **MathML→OMML**(m:nary·m:acc·m:bar 등 Presentation MathML 부분집합).
- 표: 셀 여백·헤더 음영·정렬 지정. 래스터 폴백 없음.
- 바닥글 페이지 번호(옵션) — PAGE/NUMPAGES 필드, 가운데 9pt 회색.

## UI 규약(2026-10-16, UX 루프 확립)

새 오버레이·메뉴·패널을 만들 때 따르는 규약. 기존 구현의 규칙이지
취향이 아니다 — 어기면 실제로 닫히지 않는 메뉴·읽히지 않는 선택·밀리는
버튼이 생겼다(각 규약은 회귀에서 유래).

- **오버레이 닫기 3계층**: 입력창 없는 패널은 오버레이 자체 포커스
  (`tabIndex={-1}`+마운트 시 focus)에서 ↑↓·Enter·Esc. 모달류는 App 글로벌
  Esc 체인(내보내기→스타일→인쇄→그래프→문서정보→검수→설정 순, 상호 배타).
  `closeAsk`(미저장 확인)가 열려 있으면 글로벌 Esc는 무동작.
  오버레이가 닫히면 App의 포커스 복귀 이펙트가 에디터로 되돌린다 —
  컴포넌트별 닫기에 일일이 넣지 말 것. 오버레이 플래그는 **App의
  `overlayOpen` 단일 원천**에만 추가한다(inert·Tab 트랩·포커스 복귀가
  모두 파생 — 목록을 3곳에 나눠 적다 빠뜨린 사고가 두 번 났다).
- **팝업·메뉴**: 창 전역 `pointerdown` 닫기에 **메뉴 자체는 제외**
  (`closest(".ctx-menu")` 등) — 항목 클릭이 언마운트 시점에 의존하면 click이
  삼켜진다(React 공식 함정). 대화상자를 여는 항목은 `setMenu(null)` 명시.
  고정 좌표는 `Math.min(x, window.innerWidth - 폭)` 클램프.
- **리스트 패널 키보드**: ↑↓ 선택·Enter 주요 동작·Esc 닫기, `is-sel`
  하이라이트+`scrollIntoView({block:"nearest"})`, `onMouseEnter` 동기.
  중첩 다이얼로그가 있으면 `e.target !== e.currentTarget` 가드.
  SVG 그래프 같은 공간 뷰는 로빙 tabindex+방향키 이동(정렬 노드 우선)으로
  같은 규약을 적용한다.
- **분할 리사이저**: 드래그(포인터 캡처·**컨테이너 %** — 창 폭이 아니라
  그 페인의 플렉스 부모 폭)와 ←→ 키보드 이동을 같은 클램프·저장으로
  제공(`role="separator"`+`aria-valuenow`) — 마우스 전용 분할은 키보드
  사용자의 사각지대.
- **표 위젯 키보드 모델(엑셀 패리티)**: 일반 화살표=활성 셀 이동(단일 셀로
  접힘·헤더 행 포함), ⇧화살표=사각 확장(앵커 고정·액티브 모서리),
  Enter/⇧Enter=편집 진입·아래/위, Tab=셀 간, ⇧F10·메뉴 키=표 메뉴,
  Esc 뒤 화살표=재시작, `paintSelection`이 활성 셀 `scrollIntoView(nearest)`
  로 추종(메서드 옵셔널 콜 — jsdom 미구현). 편집 진입은 `editBeginners`
  맵(셀→begin 클로저)으로 노출 — 새 진입 경로는 이 맵에.
- **↑↓·⇧↑↓ 위젯 점프 가드의 정차 조건**: CM 수직 이동(moveVertically)은
  블록 위젯을 통과 점프한다 — 가드는 도약 구간에서 가장 가까운 '커서를
  얹을 수 있는 줄'로 끊는다. 정차 가능 = 위젯에 안 덮였거나, **편집 모드
  에선 커서가 오면 원문으로 물러나는 위젯**(수평선·수식 블록·머메이드·
  프론트매터 — `isRevealableBlockWidget`). 표는 셀 클릭 편집 전용이라
  비정차, 읽기 모드에선 위젯이 안 물러나므로 전부 비정차. 블록 위젯은
  **클릭=편집** 규칙을 지닌다(수평선 포함 전 위젯 — mousedown →
  posAtDOM → 커서 → 원문 노출).
- **종료·닫기는 하나의 확인 흐름**: ⌘W(CloseRequested)와 ⌘Q(Rust
  `ExitRequested` → 창별 `quit-requested` 이벤트 → `quit_reply` 커맨드)
  모두 `confirmDirty()` 공용 헬퍼를 탄다. 앱 종료는 `quit.rs`가 요청 번호와
  창 집합을 관리하며 모든 창의 승인 뒤에만 진행한다. CloseConfirm의 저장 실패
  보류와 초안·스타일·세션 flush가 양쪽에 상속된다.
- **입력창+가상 선택(팔레트 계열)**: 포커스는 입력창에 유지하고
  `role="combobox"`+`aria-activedescendant`(항목 id)·`listbox/option`·
  `aria-selected`로 스크린 리더에 선택 전달. 섹션 머리행은
  `role="presentation"`.
- **아이콘 전용 버튼**: `title`과 함께 `aria-label` 미러링.
- **입력 요소의 keydown은 IME 가드 필수**(한글 조합 중 Esc=조합 취소, Enter=조합
  확정이 앱 동작으로 새어 나가면 모달이 닫히고 편집이 반커밋된다).
  React 합성 이벤트의 `e.isComposing`은 **런타임에 null**(타입에는 있음) —
  `imeComposing(e)` 헬퍼(`src/app/ime.ts`, nativeEvent에서 판정)를 쓴다.
  네이티브 `addEventListener`는 `e.isComposing`이 정상 동작.
- **좁은 공간**: 오버레이가 아니라 실제 컨테이너 폭 기준 — `container-type:
  inline-size`+`@container` 등급 숨김(정보성부터 숨김, 창 밖으로 밀림 방지).
- **시스템 설정 존중**: `prefers-reduced-motion`(전역 블록이 애니메이션
  억제), `prefers-contrast: more`(보조 텍스트 AAA·테두리·포커스 링 강화).
  색 대비는 WCAG 상대휘도 공식으로 실측 — 눈짐작 금지.
- **파괴적 동작**(되돌릴 수 없는 삭제): 한 번 더 누르는 2단계 무장
  (⚠ 문구·4초 자동 해제). 파일 삭제는 휴지통 이동이 우선(복구 가능 —
  Word/Obsidian 관례), 즉시 삭제는 휴지통 없는 볼륨 폴백일 뿐.
- **i18n**: 평문 dict와 포맷터 dict(`f`)가 별개 — 항상 en/ko **쌍**으로
  추가(ko 누락은 타입이 못 잡고 런타임 크래시). 무인자 문구도 `f`에 넣으면
  `t.f.key()` 호출 필수.
- **검증→커밋**: 커맨드 체인에 파이프를 끼우면 게이트가 우회된다 —
  종료코드가 체인을 게이트할 것.

## 서비스 품질 개선 진행 기록 (2026-10-20)

전체 개선 목표는 진행 중이다. 아래는 이번 변경의 코드 수준 기록이며,
테스트·타입 검사·빌드·실행 검증 결과를 의미하지 않는다. 사용자의 리소스
사용 지침에 따라 이 단계에서는 소스와 diff만 검토했다.

### 저장·닫기·파일 이름 변경

- 수동 저장과 자동 저장은 `AppStore.writeTab`을 공유한다. 탭별 저장·이름
  변경을 직렬화하고, 다른 탭이 쓰는 경로로 동시에 저장하지 않는다.
  저장 요청 뒤의 입력은 저장 완료로 처리하지 않고 dirty와 복구 초안을 유지한다.
- 자동 저장은 충돌 중인 파일을 덮어쓰지 않는다. 초안 저장·삭제도 키별
  순서를 지켜 늦은 삭제가 새 초안을 지우지 않게 한다. 초안 DB를 열지
  못한 경우 저장 성공으로 응답하지 않는다.
- 닫기 확인은 대상 탭만 처리한다. 제목 없는 문서는 저장 위치를 선택하며,
  저장 취소·실패 또는 남은 변경이 있으면 닫지 않는다. 버림은 초안까지
  삭제하고, 삭제 실패 시 dirty를 유지한다. 템플릿 문서도 복구 대상으로 삼는다.
- 이름 변경은 탭을 닫지 않는다. EditorState·잠금·참조 보기·미저장 내용을
  유지하고, SQLite의 스타일·책갈피·메모·변경 추적 기준선과 복구 초안을
  새 경로로 옮긴다. 버전 기록은 새 경로에서도 읽도록 연결하고 원래 기록은
  남긴다. 부가 정보 이관 실패는 파일 이름 변경 성공과 구분해 경고한다.
- macOS `renamex_np(RENAME_EXCL)`과 생성 시 `create_new`로 이름 변경·
  새 파일·복제의 기존 파일 덮어쓰기 경쟁을 막는다.

### 문서 탐색

- 사이드바 파일 이름 필터, 워크스페이스 루트의 새 문서 버튼, 빈 폴더와
  검색 결과 없음 안내를 제공한다.
- 트리는 로빙 tabindex, 방향키·Home/End, Shift+F10 메뉴, 계층 ARIA를
  제공한다. 사이드바 너비도 키보드로 조절할 수 있다. 접힘 변경은 세션에 저장한다.
- 이름 변경 입력은 `.md`와 `.markdown`, 파일명 중간의 점을 보존한다.
  실패해도 입력을 유지하고 오류를 표시한다. 모달은 앱 공용 포커스 관리에 연결한다.

### 남은 점검

  확인하지 않았다. 사용자 요청이 있을 때 최소 범위로 검증한다.

  편집 버퍼를 포함한 링크 갱신, 같은 이름 문서의 구분, Markdown 링크의

- 문서 구조 편집, 워크스페이스 정리, 검색·버전 복구, 내보내기, 접근성·

### 세션 복구·외부 변경 감시 후속 개선

- `draft_gc`의 세션 밖 초안 삭제를 제거하고 `draft_list`로 복구 후보를
  열거한다. 본문은 문서별로 읽어 한꺼번에 모든 초안을 복제하지 않는다.
  초안 DB 읽기 실패는 "없음"과 구분하며, 실패한 세션 참조를 다음 저장에도 남긴다.
- 파일이 없어도 남아 있는 초안을 열고 자동 저장을 차단한다. 세션이 손상돼
  없어도 초안을 찾으며, 빈 초안·파일 탭·제목 없는 탭 순서를 보존한다.
  활성·잠금·참조 탭에는 파일 경로 또는 초안 키를 사용한다.
- 초안에 저장 기준 본문(`base_text`)과 BOM·줄바꿈 정보(`meta`)를 추가했다.
  기존 SQLite 테이블은 열을 추가해 확장한다. 기준과 디스크가 다르거나
  구버전 초안이라 기준을 알 수 없으면 복원 시 충돌로 표시한다.
- 문서 열기와 복원은 스타일·책갈피·메모·변경 추적 기준선 조회를 공유한다.
  명령 팔레트의 "미저장 문서 복구 / 세션 복원 재시도"로 접근 실패 후 재시도한다.
- 감시기는 창별 범위를 합쳐 유지하고, 재귀 감시 전환 시 기존 구독을 먼저
  해제한다. 구독 실패는 성공한 경로로 기록하지 않아 다음 동기화에서 재시도한다.
- 자기 저장 뒤 일정 시간 이벤트를 버리는 처리를 없앴다. 같은 경로의 이벤트는
  마지막 변경에서 150ms 뒤 전달하되 최대 1초 지연을 두고, 디스크의 최종 상태로
  변경/삭제를 판단한다. 읽기 이벤트는 제외하고 폴더 이벤트도 열린 하위 문서에 반영한다.
- 파일 읽기 응답에는 순서를 부여하고 요청 이후 편집을 보호한다. 트리 조회와
  감시 대상 갱신은 중복 요청을 합쳐 처리하고, 이전 워크스페이스 응답은 버린다.
- 복구·SQLite 이전·감시 범위·연속 이벤트·지연 읽기 회귀 테스트 코드를
  추가했다. 이번에도 사용자 지침에 따라 실행 검증은 하지 않았다.

- `App.tsx`의 실제 IO 어댑터에 누락된 `docStyleGet`·`docStyleSet` 연결을
  추가했다. SQLite 조회 실패는 없는 스타일과 구분해 안내한다.
- 스타일 쓰기는 탭별 디바운스와 본문 저장·이름 변경에 사용하는 문서 작업
  큐를 거친다. 타이머가 실행될 때 활성 탭을 다시 조회하지 않으며, 쓰기 중의
  추가 변경도 마지막 값까지 순서대로 저장한다.
- 스타일 저장 실패는 대기 항목으로 남긴다. 본문이 수정되지 않은 문서도
  저장 명령으로 스타일만 재시도하며 `.md`는 다시 쓰지 않는다.

  기록한다. 이름 변경은 대기 스타일 쓰기를 먼저 끝내고, 변경 도중의 새
  스타일은 새 경로에 기록한다.
- 스타일 패널은 스토어의 현재 값을 표시한다. 초기화도 같은 저장 큐를 사용해
  직접 삭제 요청과 쓰기가 경합하지 않게 했다.
- 탭 닫기·창 닫기·메인 창의 종료 절차에서 스타일 저장 완료를 기다린다.
  스타일/세션 저장 실패를 무시하고 닫던 경로는 보류·오류 안내로 변경했다.
  창 닫기와 종료의 중복 요청도 해당 창에서 한 번만 처리한다.
- 탭 전환·연속 변경·실패 재시도·제목 없는 문서 복구·다른 이름으로 저장·
  이름 변경·닫힌 탭의 대기 쓰기에 대한 회귀 테스트 코드를 추가했다.
  사용자 지침에 따라 테스트·타입 검사·빌드는 실행하지 않았으며 코드와
  호출부만 검토했다. 전체 서비스 품질 목표의 완료를 의미하지 않는다.


### 여러 창의 앱 종료 조율 (2026-10-21)

- 메인 창 하나의 확인만으로 종료하던 `exit_confirmed`를 제거했다.
  Rust 종료 조율기가 현재 창 목록과 요청 번호를 보관하고, 각 창에
  `emit_to`로 순서대로 확인을 요청한다. 모든 창이 승인해야 앱을 종료한다.
- 응답한 창의 식별자는 Tauri가 주입한다. 다른 창의 선행 승인, 중복 응답,
  취소한 요청의 늦은 응답으로 종료가 진행되지 않는다. 초기 리스너 설치가
  늦은 경우 `quit_pending`으로 현재 요청을 조회한다.
- 기존 저장·이름 변경 작업이 끝난 뒤 미저장 확인을 진행한다. 초안·문서
  스타일·세션 저장 실패는 종료를 보류하며, 종료 직전 초안 쓰기 오류도
  호출자에게 전달한다. 창 위치는 창 닫기와 앱 종료에서 함께 기록한다.
- 승인한 창은 다른 창의 확인이 끝날 때까지 편집·메뉴·드롭을 막고 취소
  버튼을 표시한다. flush 도중이나 승인 후 본문·경로·스타일 등이 바뀌면
  종료를 취소한다. 다른 대화상자나 작업이 진행 중이면 안내 후 보류한다.
- 어느 창에서든 취소하면 대기 창을 풀고, 이번 종료에서 버리기를 선택했던
  버퍼의 미저장 표시와 복구 초안을 되살린다. 실제로 저장한 파일은 되돌리지 않는다.
  새 창 생성·외부 파일 열기·창 소멸도 진행 중인 종료를 취소한다.
- 조율기 순서·중복/이전 응답·취소·창 집합 변경과 초안 쓰기 실패·버림 복구·
  진행 중 저장 대기에 대한 회귀 테스트 코드를 추가했다. 사용자 지침에 따라
  테스트·타입 검사·빌드·앱 실행은 하지 않았고 소스와 호출부만 검토했다.
- 응답하지 않는 창을 시간 제한으로 강제 종료하지 않는다. 같은 파일을 여러
  창에서 편집할 때의 공유 초안 키 충돌과 비동기 편집 작업 전반의 종료 경계,
  실제 Tauri 이벤트 순서·다중 창 동작 검증은 별도 개선/확인 대상으로 남아 있다.


### 저장 시 디스크 기준 확인과 창별 메뉴 처리 (2026-10-21)

- `write_document`는 저장 조건(`match`/`missing`/`overwrite`)을 필수로 받는다.
  기존 문서 저장은 마지막 저장 본문과 BOM·줄바꿈 정보를 디스크와 비교한다.
  파일 감시가 늦어도 다른 창의 저장이나 삭제를 확인하면 쓰기를 거부하고
  `conflict`/`removed` 오류로 편집 버퍼와 미저장 상태를 유지한다.
- 앱 내부의 비교-쓰기와 파일 이름 변경은 같은 잠금을 사용한다.
  워크스페이스 찾아바꾸기와 위키링크 갱신도 읽은 버전을 쓰기 직전에 확인한다.
  일괄 작업의 일부 파일을 이미 쓴 뒤 실패하면 전체 롤백은 하지 않는다.
- ‘내 버전 유지’는 선택 시점에 읽은 디스크 버전에 대한 다음 수동 저장 승인이다.
  자동 저장으로 교체하지 않고, 승인 후 다시 바뀐 파일은 다시 충돌로 안내한다.
  삭제된 파일의 재생성은 해당 경로가 여전히 비어 있을 때만 허용한다.
- 새 문서는 완성된 임시 파일을 하드 링크로 빈 경로에 설치하여 기존 파일을
  덮어쓰지 않는다. 다른 이름으로 저장에서 대화상자로 선택한 대상 교체는
  `overwrite`를 사용한다. 임시 파일은 고유 번호와 `create_new`로 생성해
  이전 임시 파일/심볼릭 링크를 덮어쓰지 않는다.
- 네이티브 메뉴 이벤트는 현재 포커스가 있는 창에만 전달한다. 보조 창에서도
  저장·찾기·내보내기 등의 메뉴가 해당 창의 문서를 대상으로 동작한다.
- 두 쓰기 작업의 동일 기준 경합, 삭제·메타데이터 변경, 두 스토어 간 오래된
  저장 거부, 승인 후 재변경, 새 문서 생성 충돌에 대한 회귀 테스트 코드를
  추가했다. 사용자 지침에 따라 실행 검증은 하지 않고 코드와 호출부만 검토했다.
- 디스크 부족으로 중단됐던 프런트 연결까지 반영했다. 빌드 캐시는 삭제하지 않았다.
  실제 Tauri 동작과 외부 편집기의 비교-rename 사이 쓰기는 검증/추가 보완이
  필요하다. 잠금은 같은 앱 프로세스에만 적용되며 외부 프로세스까지 원자적
  비교-교체를 보장하지 않는다. 여러 창의 초안 키 분리는 아래 후속 변경에 반영했다.


### 창·탭별 초안 분리와 복구본 보존 (2026-10-21)

- 파일 탭에도 고유 초안 키를 부여하고 저장·다른 이름으로 저장·이름 변경
  후에도 유지한다. 초안 저장·삭제·버림은 파일 경로 대신 자기 키만 사용해
  다른 창의 미저장 내용을 덮거나 지우지 않는다.
- 세션은 파일 경로와 초안 키를 함께 기록하며 활성·잠금·참조 탭도 초안 키로
  구분한다. 구버전 세션의 경로 참조와 기존 경로 기반 초안은 계속 읽는다.
- 같은 파일에 여러 초안이 있으면 각각 복원하고 탭에 `(1/2)`처럼 번호를
  표시한다. 구버전 세션의 기본 탭에는 최신 초안을 연결하고 나머지도 남긴다.
  초안에 기록된 경로가 세션보다 최신이면 그 경로로 다시 읽는다.
- 같은 파일의 복구 탭도 개별 저장할 수 있다. 앞선 저장으로 디스크가 바뀌면
  뒤의 저장은 디스크 기준 비교에서 보류된다. 파일 감시는 같은 경로의 모든
  탭에 적용하고 자기 저장의 무시 범위도 해당 탭으로 제한한다.
- 복구 탭이 여러 개 열린 파일의 이름 변경은 정리 후 진행하도록 안내한다.
  백엔드 이름 변경은 각 초안 키를 유지한 채 연결 경로만 갱신한다.
- 초안 저장소는 실행 중인 창의 사용권을 메모리에 보관한다. 다른 살아 있는
  창이 쓰는 초안은 복구 목록에서 제외하고 조회·쓰기·삭제도 거부한다.
  창이 사라지면 다음 접근 시 사용권을 해제하며, 닫힌 창의 늦은 쓰기는 거부한다.
- 두 창의 저장·닫기 격리, 여러 복구본과 세션 참조, 저장 후 키 유지·경로 복원,
  살아 있는 창의 초안 보호·종료 후 복구, 이름 변경 중 키 보존에 대한 회귀
  테스트 코드를 추가했다. 테스트·타입 검사·빌드·앱 실행은 하지 않았다.
- 실제 여러 창의 종료·재시작·복구 경합 확인은 남아 있다. 문서 스타일·메모 등
  경로 기반 부가 데이터의 창 간 동시 편집, 파일 이름 변경의 창 간 전파와
  파일 시스템·DB·세션을 함께 다루는 실패 복구도 후속 개선 대상이다.


### 워크스페이스 검색·일괄 바꾸기 검토 흐름 (2026-10-21)

- 검색 상태를 입력 없음·검색 중·실패·결과 없음으로 구분하고 재시도를 제공한다.
  검색어 삭제, 폴더 변경, 옵션 변경, 패널 해제 때 이전 응답을 무효화한다.
  대소문자 옵션을 검색 요청에도 전달하고 첫 결과를 키보드로 바로 열 수 있게 했다.
- 결과는 최대 2,000줄을 표시한다. 백엔드에서 한 줄을 더 조회하여 실제로
  잘린 경우만 제한 안내를 표시한다. 검색·교체·하이라이트는 원문 문자 경계에서
  비교해 소문자 변환으로 길이가 늘어나는 유니코드 문자 앞뒤 위치를 보존한다.
- 즉시 실행하던 `replace_workspace`를 `preview_replacement`와
  `apply_replacement`로 나눴다. 미리보기는 파일별 실제 변경 횟수와 첫 변경 줄의
  전후 내용을 보여주며 파일을 쓰지 않는다. 적용 버튼은 미리 본 파일과 원문
  버전에만 적용하고, 미리보기 이후 추가된 파일은 건드리지 않는다.
- 백엔드 계획은 창에 귀속된 단일 캐시에 보관하고 한 번만 소비한다. 유효기간은
  5분이며 다른 미리보기가 생성되면 이전 계획은 무효화된다. 파일당 읽기 4MiB,
  계획의 원문+변경문 합계 16MiB, 500개 변경 파일로 제한해 메모리 사용을 제한한다.
  너무 큰 출력은 문자열을 만들기 전에 거부한다.
- 적용 전 현재 창의 대상 미저장·충돌 탭을 다시 확인한다. 각 파일은 검토한 원문과
  디스크를 비교한 뒤 쓰며, 실패한 파일이 있어도 성공·실패 목록을 모두 반환한다.
  접근 실패·인코딩 문제·크기 제한·폴더 탐색 실패도 미리보기와 결과에 남긴다.
- 교체 전 원문은 일반 스냅숏의 최소 간격과 무관하게 버전 기록에 보관한다.
  백업 실패 시 해당 파일은 쓰지 않는다. 스냅숏 쓰기를 직렬화하고 동일 시각의
  다른 내용을 별도 버전으로 남긴다. 잘못된 ‘파일별 ⌘Z 복원’ 문구는 제거했다.
- 원문 무변경 미리보기, 정확한 교체 횟수, 검토 후 디스크 변경/새 파일, 백업 실패,
  유니코드 비교와 하이라이트, 최소 간격 안의 필수 백업 회귀 테스트 코드를 추가했다.
  사용자 지침에 따라 테스트·타입 검사·빌드·앱 실행은 하지 않았다.
- 전체 적용은 파일별 작업이며 트랜잭션 전체 롤백은 제공하지 않는다. 적용 도중
  프로세스 종료의 지속적인 작업 기록, 다른 창의 아직 초안으로 기록되지 않은 입력,
  실제 대규모 폴더/느린 볼륨의 응답성·취소, 전체 서비스 품질 검증은 남아 있다.


### 버전 선택의 정확성과 복원 전 보존 (2026-10-21)

- 최신순 목록의 인덱스를 오래된 순서의 조회 목록에 적용하던 오류를 수정했다.
  목록 선택·조회·미리보기는 스냅숏 시각을 공유하며, 이전 선택의 늦은 응답은
  무시한다. 패널을 열 때의 탭 ID·경로를 고정해 다른 문서로 대상을 바꾸지 않는다.
- 복원은 탭별 문서 작업 큐에서 처리한다. 현재 버퍼를 필수 스냅숏으로 보관하고,
  백업 성공 후에도 탭·경로·본문 참조·잠금 상태를 다시 확인한다. 백업 실패나
  대기 중 문서 변경 시 본문을 교체하지 않는다. 복원은 독립된 실행 취소 단위다.
- 복원은 기존 자동 저장 설정을 따른다. 자동 저장이 켜져 있는데도 수동 저장
  전에는 파일이 바뀌지 않는다고 안내하던 문구를 실제 동작에 맞게 수정했다.
  백업은 최대 30개 버전의 기존 보관 정책을 따르며 영구 보관본은 아니다.
- 목록·본문 조회 실패를 빈 기록이나 무한 로딩으로 숨기지 않고 재시도와 오류를
  제공한다. 백엔드 목록은 없는 디렉터리만 빈 목록으로 반환하고 나머지 오류를
  전달한다. 스냅숏의 BOM·CRLF는 일반 문서와 같은 방식으로 정규화한다.
- 목록에 키보드 탐색·선택 상태·절대 시각을 제공한다. 전역 Enter 복원을 제거해
  보기/닫기 버튼의 키 입력으로 문서가 복원되지 않게 했다. 복원 중 중복 실행과
  패널 닫기를 막는다. 큰 문서는 비교 대신 최대 200,000자의 미리보기를 표시하되
  복원에는 전체 내용을 사용한다.
- 공용 줄 비교는 DP 메모리를 약 16MB로 제한하고, 큰 입력은 공통 접두·접미
  사이를 삭제+추가로 표시한다. 중복 줄을 잘못 same 처리하거나 끝부분을 생략
  안내라는 가짜 추가 줄로 대체하지 않는다. 큰 중앙 영역은 최소 편집량과 다를 수 있다.
- 버전 순서/늦은 응답/Enter 오작동/조회 재시도, 백업 실패/대기 중 편집·탭 전환·
  잠금/실행 취소, 기록 조회 오류/줄 끝 정규화, 큰 diff의 양쪽 원문 재구성에 대한
  회귀 테스트 코드를 추가했다. 사용자 지침에 따라 테스트·타입 검사·빌드·앱
  실행은 하지 않았다. 실제 Tauri UI·파일 시스템에서의 복원 확인은 남아 있다.


### 이미지 정리 후보와 휴지통 이동 (2026-10-21)

- 기존 `find_orphan_assets`가 Markdown 전용 탐색기로 이미지까지 찾으려 해
  항상 빈 목록을 만들던 문제를 전용 `md_core::assets` 모듈로 수정했다.
  워크스페이스 안의 중첩된 `assets/` 폴더도 검사한다.
- 문서 원문·열린 편집 버퍼·저장된 모든 복구 초안에서 파일명이 보이면 후보에서
  제외한다. URL 인코딩, 기본/숫자 HTML 엔티티, Markdown 이스케이프, Unicode
  NFC 및 대소문자 차이를 보수적으로 처리한다. 같은 파일명의 별개 이미지나
  일반 텍스트 언급도 보존되므로 완전한 의존성 분석은 아니다.
- 공용 URL 복호가 `%한글`처럼 잘못된 이스케이프 뒤의 UTF-8 문자 경계를
  자르며 패닉을 낼 수 있던 부분도 바이트 단위 판정으로 바꿨다. 정상 인코딩과
  잘못된 퍼센트 표기의 회귀 테스트 코드를 추가했다.
- 숨김 Markdown 문서도 검사하며 VCS 메타데이터 폴더는 제외한다. 읽기 실패,
  UTF-8 오류, 심볼릭 링크, 해석하지 못한 엔티티, 검사 한도 초과 시 정리를
  중단하고 오류를 전달한다. 파일당 본문 4MiB, 전체 본문 64MiB, 항목 20,000개,
  깊이 32, 문자열 비교량에 한도를 두었다. Unicode 정규화는 기존 lockfile에
  있던 `unicode-normalization`을 md-core의 직접 의존성으로 연결했다.
- 검수 화면에서 후보를 개별/전체 선택하고 확인 후 이동한다. 전체 목록은 스크롤로
  볼 수 있으며, 폴더/버퍼 변경 후에는 재검사가 필요하다. 스캔 실패를 빈 목록으로
  표시하지 않는다. 성공 경로와 파일별 실패를 남기고 실패 파일을 목록에서 지우지 않는다.
  활성 문서가 없어도 워크스페이스 이미지 검사를 표시한다.
- 적용 요청은 워크스페이스·선택 파일의 크기/메타데이터 정체성·현재 버퍼를 전달한다.
  백엔드는 참조를 다시 스캔한 뒤 현재 후보와 일치하는 파일만 처리하고, 경로
  canonicalize와 일반 파일 여부를 이동 직전에 다시 확인한다. 앱 내부 문서 쓰기는
  이 구간과 직렬화한다. `move_to_trash` 실패 뒤 `remove_file`하던 폴백을 제거했다.
- 다른 창의 아직 초안으로 기록되지 않은 입력까지는 직접 조회하지 못하므로
  여러 웹뷰가 열려 있으면 실제 이동을 거부한다. 영구 삭제는 수행하지 않는다.
  외부 앱의 최종 확인과 이동 사이 변경, 워크스페이스 밖의 참조, HTML/MDX 같은
  비-Markdown 파일의 참조까지 보장하지 않는다. UI도 확정된 미사용 파일 대신
  검토할 후보라는 범위와 폴더 밖 사용 여부 확인을 안내한다.
- 실제 이미지 탐색·중첩 폴더·URL/엔티티/Unicode/초안 참조·검토 후 참조 추가/
  파일 교체·영역 밖 경로·심볼릭 링크·휴지통 실패·부분 결과에 대한 테스트 코드를
  추가했다. UI 선택/확인/부분 실패/문서 변경/스캔 실패 테스트 코드도 추가했다.
  사용자 지침에 따라 테스트·타입 검사·빌드·앱 실행은 하지 않았으며 실제 파일을
  삭제하거나 휴지통으로 옮기지 않았다. 최근 문서 목록 개선은 후속 작업으로 남아 있다.


### 최근 문서 공유 상태와 기록 정리 (2026-10-21)

- 실제 App IO 어댑터에서 누락됐던 최근 목록 조회를 연결했다. 시작 화면과
  사이드바는 `RecentDocuments`를 공유하며 명령 팔레트도 같은 스토어 목록을
  구독한다. 팔레트가 열릴 때 전체 폴더를 다시 스캔하던 중복 IO도 제거했다.
- `read_document`/`write_document`의 암묵적인 최근 기록 변경을 제거했다.
  명시적인 파일 열기(이미 열린 탭 재선택 포함)·수동 본문 저장에서 기록하고,
  세션 복구·외부 변경 확인·자동 저장은 최근 순서를 바꾸지 않는다. 새 경로로
  이름 변경한 경우 이전 경로 제거와 새 경로 기록을 하나의 목록 변경으로 저장한다.
- 백엔드는 목록의 복사본을 먼저 저장하고 성공 후 메모리/순번을 갱신한다.
  실패 시 기존 목록을 유지한다. 변경한 스냅숏과 실행 중 순번을 이벤트·명령
  응답으로 전달하며 프런트는 이전 순번을 무시한다. 같은 창의 기록/제거/비우기는
  요청 순서대로 실행하고 종료 전 진행 중인 최근 기록 작업도 기다린다.
- 메뉴는 목록 잠금을 놓은 뒤 메인 스레드에서 최신 상태로 다시 구성한다.
  변경 없는 기록 요청은 디스크 쓰기·이벤트·메뉴 재구성을 생략한다.
  이름이 같은 최근 파일은 네이티브 메뉴에도 부모 경로를 함께 표시한다.
- UI에 개별 기록 제거, 전체 기록 비우기, 전체 보기, 부모 경로, 로딩·실패·재조회
  상태를 제공한다. 파일 자체는 삭제하지 않는다. 네이티브 메뉴에서 비우기 실패도
  토스트와 목록 오류로 전달한다. 파일 열기 실패를 저장 실패라고 표시하던 문구를
  열기 실패로 수정했다.
- 저장 실패 시 메모리 보존, 저장 후 순번 변경, 늦은 조회 응답, 변경 요청 순서,
  이미 열린 문서의 기록, 자동 저장 시 순서 유지에 대한 회귀 테스트 코드를 추가했다.
  테스트·타입 검사·빌드·앱 실행은 사용자 지침에 따라 실행하지 않았다.
- 실제 다중 창 이벤트/네이티브 메뉴 동작 확인, 손상된 과거 recent.json의
  백업 복구, 이동된 문서의 새 경로 찾기 UX는 남아 있다. 접근할 수 없는 파일을
  자동 제거하지 않아 오프라인 외장 볼륨의 기록도 유지한다.


### 워크스페이스 전환과 부분 탐색 상태 (2026-10-21)

- 폴더 전환은 경로·열림 상태를 즉시 반영하고 이전 트리·위키 인덱스·백링크
  캐시를 분리한다. 스캔은 기존처럼 직렬로 합치되 경로와 세대 번호를 함께
  확인해 A→B→A나 조회 중 닫기에서도 이전 응답을 적용하지 않는다.
- 같은 폴더 재조회 실패 시 마지막 목록을 유지하며 오류와 오래된 목록임을
  표시한다. 최초 조회 실패를 빈 폴더로 표시하지 않는다. 새로고침·재시도와
  로딩 상태를 제공하고 로컬 이미지 접근 허용 실패도 숨기지 않는다.
- `scan_workspace`는 트리와 경로별 문제를 함께 반환한다. 루트가 없거나 열 수
  없으면 실패하며, 하위 폴더/항목 조회 실패는 읽을 수 있는 형제 목록을 유지한
  부분 결과로 전달한다. 파일명 인코딩 오류도 잘못된 경로로 변환해 열지 않는다.
- 빈 하위 폴더도 표시해 새 문서를 만들 위치로 사용할 수 있다. 숨김·무시 폴더와
  심볼릭 링크는 계속 제외한다. 깊이 12·항목 20,000개 제한에 도달하면 누락된
  경로를 명시하며 UI에서 더 작은 폴더를 열도록 안내한다. 문제 목록은 앞의
  50개를 표시한다. 명령 팔레트도 로딩·실패·부분 탐색 상태를 함께 보여준다.
- 백링크 조회에 세대 검사를 적용하고 폴더 전환/닫기/트리 갱신 때 캐시와
  표시 개수를 무효화한다. 이전 폴더 응답이나 이미지 접근 오류가 새 폴더에
  나타나지 않도록 했다.
- 이전 트리 즉시 분리, 같은 폴더 실패/재시도, 부분 결과, A→B→A, 조회 중 닫기,
  늦은 이미지 접근 오류와 백링크 응답, 없는 루트/빈 폴더, 깊이/항목 제한,
  잘못된 경로 인코딩에 대한 회귀 테스트 코드를 추가했다. 기존 스캔 IO 모의
  구현도 새 반환 계약에 맞췄다. 사용자 지침에 따라 테스트·타입 검사·빌드·앱
  실행은 하지 않았다.
- 진행 중 파일 시스템 호출 자체를 취소하지는 않는다. 느린 네트워크 볼륨의
  오래된 스캔이 끝나야 다음 스캔이 시작된다. 매우 큰 폴더의 점진적 로딩과
  실제 접근 권한/다중 창/파일 감시 경합 검증은 후속 작업으로 남아 있다.


### 설정 저장 큐와 창 사이의 병합 (2026-10-21)

- 설정 시트·명령 팔레트·단축키·찾기/내보내기 옵션을 스토어의 단일 패치 저장
  경로로 통합했다. 화면에는 즉시 반영하며 300ms 동안 모은 변경 항목만 보낸다.
  설정 시트를 닫아도 큐는 유지되고 정상 종료 전에 남은 설정을 저장한다.
- `patch_settings`는 설정 쓰기 잠금 안에서 최신 값에 패치를 병합하고 파일 저장
  성공 후 메모리와 순번을 갱신한다. 여러 창이 서로 다른 항목을 수정해도 전체
  설정을 덮어쓰지 않는다. 같은 항목은 서버에서 마지막으로 수락한 쓰기가 이긴다.
  알 수 없는 키·null·타입/열거형 오류는 패치 전체를 거절한다.
- 저장은 고유 임시 파일·동기화·원자적 교체를 쓰는 공통 파일 저장 경로를 사용한다.
  읽기와 쓰기 명령은 작업 스레드에서 수행한다. 메뉴 갱신은 잠금을 놓은 뒤 메인
  스레드에 예약하며 메뉴 오류를 이미 성공한 설정 저장의 실패로 반환하지 않는다.
- 조회·응답·이벤트는 실행 중 순번을 포함한다. 프런트는 오래된 스냅샷을 무시하고
  서버 확정값 위에 자기 미확정 패치를 합친다. 항목별 편집 번호를 사용해 저장 중
  다시 입력한 값은 이전 응답으로 지우지 않는다. 이벤트 구독 직후 최신 값을
  다시 읽어 초기 조회와 구독 사이의 변경도 보충한다.
- 저장 실패 시 변경을 메모리에 유지하고 설정 시트와 편집 화면에 오류/재시도를
  표시한다. 실패한 저장은 무한 반복하지 않으며 새 편집·재시도·종료 시 다시
  시도한다. 종료 저장 실패 시 창 닫기를 취소한다. 브라우저 모드에는 저장소를
  연결하지 않아 로컬 변경을 저장 대기로 표시하지 않는다.
- 저장 중 재편집, 다른 창의 변경, 자기 이벤트가 먼저 도착하는 경우, 오래된
  응답/초기 조회, 실패 후 재시도, 저장소 없는 모드, 패치 형식 오류, 과거 고정
  임시 파일 보존에 관한 회귀 테스트 코드를 추가했다. 사용자 지침에 따라
  테스트·타입 검사·빌드·앱 실행은 하지 않았다.
- 큐는 메모리에 있으므로 강제 종료/충돌 전 미확정 설정까지 복구하지는 않는다.
  순번·잠금은 현재 앱 프로세스의 창 사이에 적용되며 외부 편집기의 settings.json
  변경 감시와 손상 파일의 백업 복구, 숫자 설정의 범위 정책은 후속 작업이다.
  실제 여러 창에서의 IPC·종료 경합은 실행 검증하지 않았다.


### 메모 저장·충돌·대화상자 수명 (2026-10-21)

- 메모 추가의 INSERT와 `last_insert_rowid` 조회가 같은 DB 잠금을 사용하도록
  변경했다. 같은 표현식 안에서 잠금을 다시 획득하던 경로를 없앴다. 메모 목록
  조회는 DB/잠금/쿼리/작업 스레드 오류를 빈 배열로 숨기지 않고 오류로 반환한다.
- 수정·해결·삭제는 ID와 문서 경로뿐 아니라 사용자가 보았던 텍스트와 해결 상태를
  SQL 조건으로 비교한다. 다른 창에서 수정·해결·이동·삭제한 메모는 오래된 요청으로
  덮어쓰지 않는다. 영향을 받은 행이 없으면 실패한다. 빈 내용·잘못된 위치·20,000자
  초과 입력은 거절한다. 메모 추가/수정/해결/삭제와 재앵커 완료 시 경로별 변경
  이벤트를 보내 다른 창의 열린 문서 목록을 다시 읽는다.
- 스토어는 문서 경로별 조회 순서를 관리하고 늦은 응답을 무시한다. 동일 경로의
  열린 탭 모두 갱신하며, 다른 탭으로 전환해도 변경 요청의 원래 문서를 재조회한다.
  조회 실패 시 마지막 목록과 오류를 보존한다. 초기 메타데이터 조회도 같은 경로를
  사용한다. 메모 변경은 해당 탭의 본문 저장/이름 변경 큐에 합쳐 순서를 유지한다.
- 추가 대화상자는 시작 시 문서 ID·경로·본문·줄을 보존한다. 문서가 닫히거나 경로/
  본문이 바뀌면 입력을 다른 위치에 적용하지 않는다. 저장된 본문 기준 줄로 변환해
  다음 본문 저장에서 이중 이동하지 않도록 했으며, 아직 저장되지 않은 새 줄은
  문서를 먼저 저장하도록 안내한다. 패널의 줄 이동도 현재 버퍼에 맞춰 변환한다.
- 메모 입력은 저장 성공 후에만 닫힌다. 실패/충돌 시 입력과 오류를 유지하며 저장
  중 중복 제출·취소·Esc·배경 닫기를 차단한다. 저장 성공 후 목록 재조회만 실패한
  경우 추가 실패로 반환하지 않고 별도 안내해 불필요한 중복 추가를 줄인다.
  입력을 버릴 때와 메모를 삭제할 때는 명시적인 확인을 제공한다.
- 패널은 열 때의 문서와 편집/삭제 시작 시의 메모 내용을 고정한다. 로딩·오류·재조회,
  문서 닫힘/이동, 미저장 문서 상태를 표시하며 일반 버튼·목록 의미와 키보드 이동을
  제공한다. 읽기 실패를 메모 없음으로 표시하지 않는다.
- 우클릭 메뉴의 조기 반환 때문에 메뉴를 닫으면 메모·링크·이미지 대화상자도
  렌더링되지 않던 문제를 수정했다. 메뉴와 대화상자를 독립적으로 렌더링하며
  우클릭 대화상자도 App의 모달/종료 차단 상태에 포함했다. 링크·이미지 수정 시
  대상 탭·본문·읽기 전용 상태를 확인해 오래된 위치로 쓰지 않는다.

### 책갈피 저장·조회·위치 보존 (2026-10-21)

- `bookmark_list`는 목록·기준 본문·프로세스 내 순번을 반환하며 읽기 실패를 빈 목록으로
  바꾸지 않는다. `bookmark_set`은 원하는 추가/제거 상태를 명시하고 기준 본문을 비교한다.
  같은 요청을 재시도해도 다시 토글하지 않으며 같은 창의 중복 제출은 차단한다.
- `doc_bookmark_context`에 좌표의 기준 본문을 보관한다. 기존 DB는 최초 조회 당시의
  저장된 본문을 기준으로 한 번 이관한다. 과거에 이미 어긋난 위치까지 복구하지는 않는다.

  전체 목록이 조회 당시와 같을 때만 목록과 새 기준을 함께 교체한다. 중간 DB 실패는
  모두 롤백하며 이후 재시도는 DB에 남은 기준에서 다시 계산한다. 실제 파일 본문이
  요청 대상과 같은지도 앱 내부 문서 쓰기 잠금 아래 확인한다. 다른 창이 이미 새 본문을
  저장한 경우 오래된 본문 기준의 위치 변경을 거절한다.
- 메모 위치 저장과 책갈피 위치 저장은 각각 실패를 처리한다. 책갈피 실패 때문에 이미
  성공한 본문 저장을 실패로 표시하지 않으며, 오류는 목차에서 재시도할 수 있게 남긴다.
  성공한 재조회만으로 실패한 쓰기 요청의 오류를 지우지 않는다.
- 요청은 탭·경로·본문을 고정하고 같은 탭의 저장/이름 변경과 직렬화한다. 조회를 기다리는
  동안 본문이 바뀌면 쓰기 전에 거절한다. 서버 순번과 경로별 조회 순서를 확인하므로
  늦은 조회가 최신 책갈피를 덮지 않는다. 다른 창의 변경 이벤트와 구독 직후 재조회도
  같은 경로를 사용한다.
- 목차 목록·우클릭 문구·다음/이전 탐색은 현재 편집 버퍼에 대응하는 줄을 사용한다.
  여러 책갈피의 이동은 한 번의 diff로 계산하고 본문·기준·목록이 같으면 재사용한다.
  빈 목록/동일 본문은 diff를 생략하고, 닫힌 목차는 위치 계산을 생략한다. 본문 배지는

- DB 비교 교체·재시도·롤백·조회 오류, 중복 토글·응답 유실·늦은 조회·본문 변경,
  편집/되돌리기 좌표와 위치 저장 실패 후 재저장에 대한 회귀 테스트 코드를 추가했다.
  사용자 지침에 따라 테스트·타입 검사·린트·빌드·앱 실행은 하지 않았다.

  반복된 줄·문단 이동·대규모 변경에서 블록 ID처럼 정체성을 보장하지 않는다. 새로 입력한
  줄은 먼저 본문을 저장해야 책갈피를 추가할 수 있다. 파일과 DB 전체의 단일 트랜잭션,
  앱 밖 파일 변경과의 완전한 원자성, 프로세스 간 영속 순번은 후속 작업이다.

### 이름 변경 검토 작업의 영속화와 재개 (2026-10-21)

- `pending_rename`에 작업 ID·원래 작업 폴더·이전/새 경로·기기/파일 식별자·단계를

  기록을 지우며 정리도 실패하면 오류와 기록을 남긴다. 성공 시 `ready`로 표시한다.

  폴더와 상하위 작업 폴더의 보류 작업은 정리 전 새 이름 변경을 허용하지 않는다.
  정규화한 실제 폴더 경로로 겹침을 확인하므로 다른 창/폴더 별칭을 통한 중복도
  막는다. 파일을 덮지 않는 기존 rename 연산과 문서 쓰기 잠금은 유지한다.
- 앱 재시작·창 재생성 후 준비 단계 기록을 읽을 때, 옛 경로가 사라지고 새 경로의
  기기/파일 식별자가 일치하면 검토 가능 상태로 복구한다. 파일을 다시 이동하거나
  본문을 자동 수정하지 않는다. 옛 경로가 남거나 새 파일이 다르면 확인이 필요한
  보류 작업으로 유지한다. 이는 파일 이동의 재실행이 아닌 검토 단계의 복구다.
- 사이드바는 저장된 작업 목록·조회 실패·중단 사유를 표시한다. 읽기 실패에도
  기존 목록을 유지하며 재조회할 수 있다. 창 간 변경 이벤트와 구독 직후 재조회,
  요청 순서 확인을 적용한다. 앱을 닫거나 작업 폴더를 바꿔도 기록은 DB에 남는다.
- 링크 미리보기는 클라이언트 경로 대신 작업 ID로 저장된 대상 정보를 조회한다.
  적용 시 작업이 아직 존재하는지 다시 확인한다. 작업별 적용·이름 변경·완료/포기를
  같은 프로세스 잠금으로 직렬화해 다른 창이 적용 중인 작업을 지우지 못하게 한다.
  미리보기 캐시 잠금을 보유한 채 이 잠금을 기다리지 않도록 잠금 순서를 정했다.
- 완료 표시도 DB에 저장된 뒤 화면에서 제거한다. 완료 직전에는 문서 쓰기 잠금
  아래 링크 후보와 읽기 실패를 다시 확인한다. 새로 남은 링크나 확인 불가능한
  문서가 있으면 재검토를 요구한다. 명시적인 “링크를 그대로 두기”는 기록만 지운다.
  응답 유실 후 완료/포기를 재시도해도 이미 제거된 ID는 성공으로 처리한다.
- 완료 기록 저장 실패 시 결과 화면과 보류 기록을 유지한다. 다시 시도하거나
  “보류 작업을 남기고 닫기”로 빠져나올 수 있다. 전체 적용 후 종료되더라도 기록이
  남아 다음 시작 때 새 미리보기로 확인하고 마칠 수 있다.
- DB 재연결·이동 전/후 중단·다른 파일로 바뀐 대상·겹치는 폴더·쓰기/완료 실패·
  최종 재확인·응답 재시도와 UI 재개/조회 실패/늦은 응답에 대한 회귀 테스트 코드를
  추가했다. 사용자 요청에 따라 테스트·타입 검사·린트·빌드·앱 실행은 하지 않았다.
- 이 기록은 링크 검토를 위한 작업 기록이다. 중단된 스타일/초안/버전 이관의 자동
  재실행, 파일과 모든 사이드카를 묶는 단일 트랜잭션, 외부 프로세스의 파일 변경을
  잠그는 기능은 아직 없다. 기기/파일 식별자 재사용과 볼륨 이동도 완전한 문서 UUID
  추적을 대신하지는 않는다. 실제 앱 강제 종료와 다중 창 경합의 실행 확인은 남았다.

### 일반 Markdown 링크의 이름 변경 전파 (2026-10-21)

- `markdown_rename`은 인라인 링크와 참조형 링크의 정의 주소를 기존 이름 변경
  검토에 포함한다. Markdown 파일을 가리키는 이미지 문법도 동일하게 처리한다.
  각 문서 폴더에서 URL을 해석해 이전 파일 경로와 일치하는 대상만 고르며, 외부
  URL·다른 폴더의 동명 파일·앵커 전용 링크는 그대로 둔다.
- 표시 문구, 링크 제목, 참조 키와 사용처, 꺾쇠 구분자 등 주소 밖의 원문을
  보존한다. 새 경로의 공백·괄호·특수문자·다국어는 percent-encoding으로 표현하며
  앵커의 의미를 유지한다. 주소의 기존 인코딩 표기는 정규화될 수 있다.
- comrak이 참조 정의의 원문 위치를 공개하지 않아, 제한된 후보 스캔 후 파싱 전용
  참조 사용처와 임시 URL로 실제 정의를 식별한다. 대소문자·공백 정규화와 중복
  정의의 우선순위는 파서에 맡긴다. 활성 정의만 한 번 바꾸며 임시 문자열은
  저장되지 않는다. 코드·HTML·메타데이터의 예제 정의는 변경하지 않는다.
- 주소 교체 전후 실제 문서의 전체 파싱 구조와 값을 비교해 대상 URL 이외의
  변화가 있거나 해석된 이전 링크가 남으면 해당 파일 전체를 보류한다. 임시
  참조 사용처도 따로 비교한다. 실제 문서는 임시 사용처 없이 비교하므로 파서의
  참조 확장 예산이 검사에 영향을 주어 링크를 놓치지 않게 한다.
- `markdown_source`가 파서 옵션, 프런트매터 마스킹, 바이트 범위와 교체 처리를
  공유한다. 위키링크와 일반 링크 편집은 같은 원본의 범위로 합치고 겹침을
  거부한다. 기존 필수 백업·비교 쓰기·BOM/줄바꿈 보존·부분 실패 보고·보류 작업
  복구와 완료 전 재조회 경로를 그대로 사용한다.
- 파일당 참조 정의 후보 512개, 후보 탐색 20,000곳, 임시 참조 문자열 256 KiB,
  주소 스캔 16 KiB와 인라인 링크 원문 64 KiB 제한을 둔다. 매핑할 수 없는
  컨테이너 내부의 여러 줄 정의 등은 추측하여 수정하지 않고 보류 사유를 표시한다.
  쿼리 문자열이 붙은 주소와 특수 스킴은 기존 링크 해석 규칙을 따른다.
  일반 링크의 백링크·그래프 통합은 아래 문서 연결 절을 따른다.
- 인라인/참조형·중복 정의·다국어/인코딩·코드/메타데이터 제외·미사용 정의·
  특수 파일명·혼합 링크/BOM/CRLF·완료 시 남은 일반 링크 재확인에 대한
  테스트 코드를 추가했다. 사용자 지침에 따라 테스트·타입 검사·린트·빌드·
  앱 실행은 하지 않았으며 파서와 편집기의 확장 문법 호환성은 실행 확인이 남아 있다.

### 백링크·그래프의 문서 연결 해석과 갱신 (2026-10-21)

- `document_links`가 위키링크와 일반 Markdown 링크의 사용처를 원문 순서대로
  추출한다. 기존 이름 변경의 위키 추출도 이 모듈을 사용한다. 참조형 링크는
  파서가 해석한 URL과 실제 사용처의 줄 번호를 사용하므로, 백링크에서 정의 줄이
  아닌 읽고 있던 문장으로 이동한다. 사용하지 않은 참조 정의는 연결로 세지 않는다.
- 백링크와 그래프가 같은 대상 해석 함수를 사용한다. 위키는 기존 색인 우선순위,
  일반 링크는 문서 폴더 기준 경로·percent-decoding·앵커 분리를 적용한다.
  실제 워크스페이스 목록에 있는 문서만 연결하며, 외부 URL·폴더 밖 경로·없는 파일·
  자기 참조를 제외한다. Markdown 파일을 가리키는 이미지 문법도 포함한다.
- 그래프 명령을 `wiki_edges`에서 `document_edges`로 바꾸고 프런트 타입·호출·
  등록을 함께 변경했다. 결과의 양 끝점은 파일 경로다. 프런트에서 파일명을 다시
  해석하지 않아 동명 문서 혼동을 줄인다. 백링크는 파일/줄 단위, 그래프는 방향이
  같은 출발/도착 단위로 중복을 제거하며 양방향 연결은 별개로 유지한다.
- 저장된 문서 본문·폴더 구성 변화의 `linksRevision`을 공유한다. 열린 문서의
  저장과 외부 변경도 기존 트리 객체가 같더라도 배지·패널·그래프 조회를 무효화한다.
  실패한 저장은 순번을 변경하지 않는다. 다른 이름 저장은 트리도 새로 읽는다.
  조회 결과는 폴더·순번·대상이 여전히 일치할 때만 반영한다.
- 패널/그래프는 250ms, 배지는 400ms로 연속 요청을 합친다. 각 조회 경로는
  진행 중인 조회 뒤 최신 요청만 실행하며 취소된 대기 요청은 스캔하지 않는다.
  오류를 연결 없음으로 숨기지 않고 패널에서 재시도할 수 있다. 백링크 모달의
  초기 포커스와 첫 결과 Enter 탐색도 수정했다.
- 문서 연결 스캔에는 파일당 4 MiB, 총 읽기 128 MiB 제한을 두며 그래프는
  고유 간선 100,000개를 초과하면 오류를 반환한다. 읽기·전체 폴더 목록 오류도
  전파한다. 그래프가 250개 노드를 넘으면 모든 노드 쌍의 힘 계산을 생략하고
  원형 좌표를 유지한다. 노드를 임의로 생략하지 않으며 배치 이유를 화면에 표시한다.
- 상대/명시 경로·동명 파일·참조 정의 중복·코드/메타 제외·인코딩·범위 밖 대상·
  읽기 실패/한도·저장 후 갱신·늦은 응답·조회 직렬화·키보드 이동에 대한 테스트
  코드를 추가했다. 사용자 지침에 따라 테스트·타입 검사·린트·빌드·앱 실행은
  하지 않았다.
- 연결은 저장된 파일을 기준으로 한다. 미저장 버퍼 반영, 여러 창에 걸친 조회 공유,
  전체 폴더의 원자적 스냅샷, 대규모 그래프의 SVG 가상화는 아직 없다. 백링크
  API의 기존 200개 결과 제한도 유지한다. 확장 문법과 실제 앱 동작은 실행 확인이 남았다.

### 워크스페이스 검색의 부분 결과와 조회 비용 (2026-10-21)

- `search_workspace`는 배열 대신 `SearchReport`를 반환한다. 검색 줄, 경로별
  누락 사유, 결과 제한 여부, 읽은 파일 수와 목록의 파일 수를 함께 전달한다.
  루트 조회 실패는 오류이며, 하위 스캔·파일 읽기·인코딩 실패는 다른 파일의
  결과를 유지하면서 표시한다. 2,000개 제한보다 많은 일치 줄을 실제로 찾았을
  때만 결과 제한을 표시한다.
- 검색과 일괄 바꾸기의 파일 목록은 사이드바의 `scan_tree`를 공유한다. 폴더
  순서·숨김/무시 항목·심볼릭 링크·깊이 12단계·20,000개 항목·경로 인코딩 규칙을
  일치시켰다. 기존 별도 재귀 수집기를 제거하고 스캔 누락을 바꾸기 검토에도 전달한다.
- 검색은 파일당 4 MiB, 전체 실제 읽기 128 MiB, 검색어 1,024자 제한을 둔다.
  읽기 실패 중 받은 바이트와 큰 파일 판별에 사용한 바이트도 예산에 포함한다.
  예산 끝에서 EOF를 확인하지 못한 파일은 일부 본문으로 결과를 만들지 않고
  보류 사유를 남긴다. 파일 수는 발견된 목록 기준이며, 읽은 파일 수는 디코딩까지
  성공한 수다. 결과 제한으로 마지막 읽은 파일의 검색이 도중에 끝날 수 있다.
- 편집기와 같은 UTF-8/BOM·줄바꿈 정규화를 사용해 검색 줄 번호를 맞춘다.
  깨진 UTF-8을 손실 변환한 가짜 문장 대신 인코딩 오류를 표시한다. 대소문자
  비구분 비교는 문자별 소문자 동등성을 유지하는 KMP로 바꾸고 검색어 전처리를
  워크스페이스 조회당 한 번 수행한다. 원본 바이트 범위와 비중첩 교체 의미는 유지한다.
- 프런트는 검색어·대소문자·폴더·저장 내용 순번이 맞는 결과만 표시한다.
  200ms 디바운스와 직렬 조회로 진행 중인 검색 뒤에는 최신 대기 요청만 실행한다.
  저장·외부 변경 후 트리 객체가 같아도 다시 읽는다. 검색 실패와 교체 실패의
  상태를 분리해 검색 갱신이 교체 오류를 지우지 않게 했다.
- 부분 결과에서는 전체 “일치 없음” 대신 읽을 수 있었던 문서의 결과임을 밝히고,
  누락 경로/사유(처음 50개)와 재시도를 제공한다. 모두 바꾸기는 적용 직전에
  편집기 내용을 동기화하고 미저장·충돌·잠긴 탭을 다시 확인한다.
- 부분 검색·정확한 제한 경계·읽기 예산·줄바꿈/인코딩·동일한 검색/교체 범위·
  Unicode/반복 접두사 비교·늦은 조회·재시도·잠금 경합에 대한 테스트 코드를
  추가했다. 사용자 지침에 따라 테스트·타입 검사·린트·빌드·벤치마크·앱 실행은
  하지 않았다.
- 검색은 저장된 파일 기준의 줄 단위 리터럴 검색이다. 실행 중인 백엔드 읽기의
  즉시 취소, 미저장 버퍼 검색, 검색 결과 페이지 넘김, 여러 창 간 조회 공유와
  전체 폴더 스냅샷은 아직 없다. 처리 시간의 실제 측정도 하지 않았다.

### 현재 본문의 끊긴 링크 검사와 대상 문서 생성 (2026-10-21)

- `broken_links`와 `inspect_links`는 미저장 내용을 포함한 현재 편집 본문을
  `document_links`로 파싱한다. 위키·인라인·참조형·이미지 사용처를 검사하며 코드,
  메타데이터와 사용하지 않은 참조 정의는 제외한다. 파일은 `metadata`로 확인하므로
  Markdown만 담긴 트리에서 이미지를 찾지 못하던 오진을 제거했다.
- 위키링크는 완전한 워크스페이스 색인을 기준으로 판단한다. 일반 경로는 기존
  링크 해석기의 상대 경로 정리·percent-decoding을 공유한다. 워크스페이스 밖
  경로, 외부로 이어진 심볼릭 링크, 끊긴 심볼릭 링크와 읽기 오류는 확인 불가로
  표시한다. 폴더 스캔 자체가 불완전하면 검사 실패로 알리고 재시도할 수 있다.
- 원문 줄 번호를 보존하고 Rust의 UTF-8 바이트 위치를 CodeMirror의 UTF-16
  위치로 변환한다. 프런트매터를 잘라서 줄 번호가 줄어들던 문제와 이모지 앞뒤의
  이동 위치 오차를 방지한다. 읽기 전용 검사 입력은 4 MiB/2,000개 사용처로 제한한다.
- `useLinkInspection`을 끊긴 링크 패널과 검수 허브에서 공유한다. 250ms 디바운스,
  진행 중인 조회 뒤 최신 요청만 실행, 문서 ID·경로·본문 객체·폴더·저장 순번
  비교를 적용한다. 이동/생성 클릭 직전에도 활성 편집 내용을 동기화해 다시 확인한다.

  링크 종류와 원래 대상을 다시 해석한다. 기존 폴더 아래의 보이는 `.md`/
  `.markdown` 대상만 생성하며, 이미지·범위 밖·숨김 경로·제어 문자·존재하는 파일은
  생성하지 않는다. 위키의 단순 이름은 원문 폴더, 경로 이름은 작업 폴더 기준이며
  루트 명시 파일 경로도 지원한다. 파일형 링크에 `.md`를 다시 덧붙이지 않는다.
- 생성은 기존 missing-only 원자적 쓰기를 사용한다. 동시에 파일이 생겨도
  덮어쓰지 않는다. 중복 제출을 막고 실패 시 패널과 오류를 남긴다. 생성 대기 중

- 브라우저 URL 복호화는 불완전한 UTF-8 퍼센트 시퀀스에도 예외를 던지지 않고
  Rust와 같은 대체 문자 규칙을 따른다. 일반 URI 스킴은 양쪽에서 로컬 경로와

  테스트 코드를 추가했다. 사용자 지침에 따라 테스트·타입 검사·린트·빌드·앱
  실행은 하지 않았다.

  부모 경로를 바꾸는 경우까지 원자적으로 잠그지는 않는다. 실제 앱과 파일시스템

### 문서 링크·검색 결과의 탐색 순서와 위치 (2026-10-21)

- `AppStore.openPath`는 선택적 제목/줄 위치를 받는다. 문서를 성공적으로 열고
  해당 요청이 여전히 최신일 때 활성화와 위치 이동을 함께 처리한다. 검색·백링크
  결과는 이 경로를 사용하므로 파일 읽기 실패 후 다른 문서의 커서를 옮기지 않는다.
- 파일 읽기는 경로별로 공유하되 탐색 요청마다 순번을 부여한다. 같은 파일을
  두 번 요청하면 마지막 위치가 적용되고, 서로 다른 파일의 읽기가 역순으로
  끝나더라도 마지막 요청이 선택을 유지한다. 대기 중 직접 탭 선택·새 탭 생성·
  활성 탭 닫기·본문 앵커 이동도 이전 요청의 활성화를 무효화한다.
  이미 요청한 읽기는 취소하지 않으며 늦게 읽힌 파일은 비활성 탭으로 남긴다.
- 일반 Markdown 링크와 위키링크의 문서 내 제목 위치를 전달한다. 정확한 slug를
  먼저 찾고 위키의 원문 제목도 허용한다. 접두사 일치로 다른 제목에 이동하던
  처리를 제거했으며 없는 제목은 알림을 표시하고 빈 fragment는 문서 처음으로 간다.
  위키 위젯이 넘기는 실제 파일 경로와 제목은 각각 URL 인코딩해 파일명의 `#`와
  `%`가 구분자나 기존 인코딩으로 해석되지 않게 한다.
- 탭 활성화의 지연된 스크롤 복원은 뷰·탭·스크롤 순번을 확인한다. 명시적인
  목적지 이동은 이전 복원을 무효화해 측정 완료 후 커서와 스크롤이 어긋나는
  경로를 막는다.
- 역순 읽기·실패·탭 전환/닫기·같은 경로 중복 요청·제목 중복/접두사·한글 제목·
  스크롤 복원·위키 URL 전달 회귀 테스트를 작성했다. 사용자 지침에 따라
  테스트·타입 검사·린트·빌드·앱 실행은 하지 않았다.
- 제목 수집은 아래 구문 기반 목차 개선에서 Setext까지 확장했다. HTML의 사용자
  지정 ID와 저장 이후 내용이 바뀐 검색 결과의 줄 재탐색은 이 변경에 포함하지 않는다.

### 클립보드 데이터 고정과 비동기 편집 보호 (2026-10-21)

- 이미지 붙여넣기는 `ClipboardEvent`의 `File`을 즉시 잡아 그 객체의 바이트와
  MIME을 저장한다. macOS 시스템 클립보드를 나중에 다시 읽던
  `save_clipboard_image` 명령을 `save_image_bytes`로 교체했다. 프런트와 백엔드
  모두 32 MiB 제한을 확인하고 Blob 읽기가 끝난 뒤에도 대상 문서를 다시 확인한다.
- Tauri의 raw IPC 본문과 ASCII로 인코딩한 디렉터리/MIME 헤더를 사용한다.
  바이트를 JSON 배열이나 base64로 변환하지 않는다. 백엔드는 명시적인 MIME
  목록에서 확장자를 고르고 파일 쓰기는 blocking 작업으로 넘긴다. 이미지 내용의
  디코딩 검증·포맷 변환은 수행하지 않는다.
- `asyncEditPlugin`은 비동기 작업의 범위를 추적한다. 문서 변경 시 이전 이미지
  가져오기와 공유하는 `mapPendingRange`로 위치를 보정하고, 범위 안의 변경이나
  읽기 전용 전환은 해당 작업을 무효화한다. `setState`로 탭이 바뀌면 플러그인이
  폐기되므로 동일한 문자열을 가진 다른 탭이나 돌아온 이전 탭에도 적용하지 않는다.
- 일반 텍스트 붙여넣기와 컨텍스트 메뉴 잘라내기/붙여넣기는 이 범위를 사용한다.
  같은 종류의 새 요청은 이전 요청을 무효화한다. 커서를 다른 곳으로 옮겼으면
  완료 시 그 선택을 유지하고, 적용한 편집은 독립된 undo 경계를 가진다.
  잘라내기는 클립보드 쓰기가 성공한 뒤에만 삭제한다. 쓰기 실패와 변경된 대상은
  화면에 알리고 원문을 보존한다. 읽기 전용 문서의 복사는 허용한다.
- 클립보드 읽기 실패 후 다음 붙여넣기를 전역 플래그로 바꾸던 처리를 제거했다.
  실패는 현재 작업에서 알리며 다른 문서나 다음 붙여넣기 동작을 바꾸지 않는다.
- 지연 HTML 변환도 같은 가드를 사용한다. 일반 텍스트가 있으면 먼저 넣고,
  그 범위를 안전하게 바꿀 수 있을 때만 Markdown으로 변환한다. 일반 텍스트가
  없으면 변환 성공 전 선택 내용을 지우지 않는다. HTML 4 Mi 문자 초과는 변환을
  생략하고 일반 텍스트를 보존한다. 변환 실패도 알림을 표시한다. 지연 변환은
  별도 undo 단계이며 대기 중 사용자의 다른 편집과 합치지 않는다.
- Blob 읽기 중 탭 전환·MIME/바이트 전달·raw IPC·동일 본문의 탭 전환·입력
  위치 보정·중복 조회·잘라내기 실패/대기·지연 HTML 처리의 회귀 테스트를
  작성했다. 사용자 지침에 따라 테스트·타입 검사·린트·빌드·앱 실행은 하지 않았다.

- 실제 WebKit 클립보드 MIME 지원과 raw IPC 전송은 실행 확인이 남아 있다.
  변환 상한 안의 HTML은 메인 스레드에서 처리하며 worker 분리나 즉시 취소는
  지원하지 않는다. 운영체제가 제공하는 기본 잘라내기/붙여넣기는 기존 브라우저
  동작을 사용하고, 여기서 명시적으로 보호하는 잘라내기는 앱 컨텍스트 메뉴다.

### 구문 기반 제목 탐색과 원문을 보존하는 섹션 이동 (2026-10-21)

  프런트매터는 기존 `frontMatterLen`과 같은 규칙으로 제외하고 오프셋을 돌려놓는다.

  구분자를 이스케이프한다. 제목의 기존 slug 생성 규칙은 유지한다.
- 명령 팔레트의 제목 검색은 프런트매터를 잘라낸 위치를 원문에 적용하던 문제를
  제거했다. 조회 당시 본문/탭을 확인하고, 탭·본문 변경 시 검색 목록을 다시 계산한다.

- 목차와 상태 줄의 제목 목록은 조회한 문서 ID/본문 객체와 함께 보관한다.

- 긴 펜스·코드/HTML/수식·Setext·원문 위치·컨테이너·중복 제목·목차 라벨·

### 밑줄형 제목(Setext) 제거 — 제목은 #/## 로만 (2026-10-21 보고, 10-24 검토 완성)

- 방침: 밑줄형 제목(`text\n---` H2 · `text\n===` H1)은 이 앱의 제목이 아니다.
  `-`/`=` 입력이 앞 줄을 제목으로 바꾸는 일을 전 경로에서 막는다. 파싱은 다른
  앱 호환·기존 문서를 위해 Lezer 표준 그대로 두고, 표시·타이핑·내보내기의
  세 층에서 Word식으로 되돌린다(`splitTableAtPlainLine`과 같은 패턴).
- 렌더(`livePreview`): Setext 노드의 HeaderMark 자식 범위로 밑줄을 판정한다 —
  줄 원문에는 인용구 마커(`> ---`)가 붙어 인용구 안에서만 제목이 되는 구멍이
  있었다. 대시 3개+는 문단+수평선 위젯, 그 외(대시 1-2·= 전부)는 원문 그대로.
  제목 크기 태그 하이라이트(t.heading*)는 제거 — 라인 클래스(md-h1~6)가
  유일한 원천(태그 fontSize가 장식 억제를 우회해 크게 보였다). 대신 소스
  모드에서만 제목 모양을 준다(2026-10-24): 태그에 클래스(md-tag-h*)만 붙이고
  스타일은 `cm-source-mode` 스코프 CSS로 — 소스 모드는 '원문 그대로'라
  CommonMark 해석(comrak가 H2/H1로 읽을 것)이 드러나는 게 정직하다.
- 타이핑 가드(`cm.ts` `splitSetextUnderline`, input.type): (A) 밑줄 줄 완성
  순간 위에 빈 줄 삽입(대시·등호 모두 3개+. 1-2개는 목록 시작·수학식 흐름
  등이라 제외 — 렌더 억제와 내보내기 정규화가 흡수),
  (B) 이미 짝인 문단을 편집하면 사이에 빈 줄. 트리(SetextHeading1/2) 확인으로
  코드 블록 내부 등 오탐 없음. 인용구 밑줄은 마커를 걷어내 판정하고 분리는
  줄 시작에(인용구는 끝나고 구분선). 변경 줄 전체 순회(멀티커서).
- 스마트 문장부호(`smartPunct`): 커서 줄이 공백·대시류로만 이뤄지면(수평선
  입력 중) `--→–` 변환을 건너뛴다 — 실제 입력 경로(inputHandler)에서만
  발생해 `---`이 `–`로 바뀌어 완성 자체가 안 되던 보고를 해결.
- 목차(`links.ts`): 밑줄형 setext 제목을 수집하지 않는다(렌더와 일관).
- 내보내기(`export/snapshot.ts`): 본문에 `normalizeUnderlineRules`를 적용해
  setext 짝에 빈 줄을 넣는다(인용구 짝은 빈 인용 줄) — comrak(CommonMark)가
  H2/H1으로 해석하던 붙여넣기·오래된 문서 경로를 흡수한다. 삽입 줄 번호로
  DOCX 코멘트 줄번호를 보정한다. 트리 기반이라 코드 블록 오탐 없음.
- 문서 첫 줄 `---` 삼킴 방지(`frontmatter.ts`): 닫는 `---`이 있을 때만
  프론트매터로 파싱(FM_SCAN과 같은 규칙). 미리보기에 Lezer 내부 `scanLine`
  을 쓰며 없으면 탐욕 폴백 + 콘솔 경고 1회.

### 제목 앵커 충돌과 DOCX 내부 링크 (2026-10-21)

- `createHeadingSlugger`/`HeadingSlugs`는 이미 발급한 모든 제목 ID를 예약한다.

  링크 동작이나 북마크 이름 호환성은 이번 작업에서 실행 검증하지 않았다.

### EPUB 저장 실패 보존과 이미지 경로 해석 (2026-10-21)

- `md-core::io::write_file_atomic`은 기존 바이트 저장과 임시 파일 처리 코드를
  공유하며, ZIP을 파일에 직접 작성하는 콜백을 받는다. EPUB은 중앙 디렉터리
  작성까지 성공하고 fsync한 뒤 최종 파일을 교체한다. 오류 반환 시 임시 파일을
  지우며 기존 출력은 유지한다. 생성 중에는 문서 쓰기 잠금을 잡지 않고 최종
  교체에만 잠금을 사용한다. 완성 ZIP 전체를 메모리에 복제하지 않는다.
- EPUB 챕터 파일명은 단일 ASCII XHTML 이름으로 제한하고 중복 및 패키지의
  예약 이름을 거부한다. XHTML 본문 오류도 최종 파일 교체 전에 반환한다.
- 이미지 임베딩은 roxmltree로 XHTML의 img/src만 읽는다. XML 엔티티 복호 후
  URL 경로를 percent-decode하며, 따옴표 종류와 등호 주변 공백에 의존하지
  않는다. 주석·텍스트·data-src는 그대로 두고 동일 파일은 한 번만 포함한다.
  로컬 이미지의 fragment는 유지하고 파일 읽기에 불필요한 query는 제외한다.
- 누락된 로컬 이미지·표지나 미지원 확장자는 경로를 포함한 오류로 알린다.
  원격/데이터 URI와 `//host` 경로는 로컬 파일로 읽지 않는다. MIME은 명시된
  이미지 확장자 표를 사용하며 알 수 없는 확장자를 PNG로 표시하지 않는다.
- 표지 선택은 렌더링된 본문에서 첫 로컬 img를 찾는다. 코드 예시는 제외하고,
  참조형 이미지·한글·공백·엔티티·상위 폴더 경로를 본문과 같은 의미로 해석한다.
- 생산 콜백의 부분 쓰기 후 실패·seek 성공·잠금 범위, 잘못된 XHTML/누락
  이미지/표지/챕터 이름에서 기존 EPUB 바이트 보존과 임시 파일 정리,
  이미지 속성 해석 및 표지 선택의 회귀 테스트를 작성했다. 실행하지 않았다.
- 정상 오류 반환에 대한 보호이며 강제 종료 뒤 임시 파일 회수나 외부 프로그램의
  동시 출력 변경을 비교하는 CAS는 제공하지 않는다. 이미지 바이트의 디코딩
  검증, 대량 이미지 메모리 예산, SVG 내부 외부 자원 포함은 남아 있다.

### DOCX 메모 보존과 블록 연결 (2026-10-21)

- `DocxComments`는 줄 번호별 메모 목록을 보관한다. 같은 줄의 메모를 하나로
  덮어쓰지 않으며, 각 메모의 정의·범위 시작/종료·참조가 개별 ID를 사용한다.
  자식 블록에서 연결한 메모는 부모에서 다시 연결하지 않는다.
- 일반 문단의 계속 줄, 제목, 목록 항목, 인용, 표 행, 일반 코드 줄, 표 캡션에
  메모를 연결한다. 표 행 메모는 첫 셀에, 블록 전체에 해당하는 나머지 메모는
  해당 블록의 첫 출력 문단에 연결한다. Word의 문자 단위 범위 선택은 아니다.
- 빈 줄이나 생략되는 raw HTML, 본문에서 추출한 각주 정의의 메모는 소스
  위치에 빈 문단 앵커를 남긴다. 본문 XML에 연결되지 않은 메모 정의만 따로
  저장하던 문제를 없앤다. 컨테이너 내부의 빈 줄 등은 블록 단위 연결을 따른다.
- 각주 정의와 들여쓴 계속 줄을 추출할 때 빈 줄을 남겨 이후 본문의 줄 좌표를
  유지한다. 일반 코드의 앞뒤 빈 줄도 보존해 코드 줄의 메모 좌표와 맞춘다.
  범위를 벗어난 메모 줄 번호는 기존 DOCX를 교체하기 전에 오류로 반환한다.
- 동일 줄 메모·중복 연결 방지·빈 앵커·각주 이후 위치·제목/문단/목록/인용/
  표/코드의 실제 생성 XML을 읽는 회귀 테스트를 추가했다. 메모 본문과 참조의
  일대일 대응 및 연결된 문단 텍스트를 확인하도록 작성했으며 실행하지 않았다.
- Word에서의 시각적 메모 표시와 실제 호환성은 실행 검증하지 않았다.
  각주 추출기는 아래 단계에서 파서 기반으로 교체했다. 인용 전처리 전체의
  구문 일관성은 추가 개선이 필요하다.

### DOCX 파서 기반 각주와 자원 연결 (2026-10-21)

- Comrak의 footnotes 확장을 사용하고 정의 노드를 원래 소스 위치에 유지한다.
  줄 스캔으로 정의를 추출하고 본문 XML의 사설 문자 센티넬을 치환하던 코드는
  제거했다. 코드 펜스·인라인 코드·이스케이프된 표기는 실제 참조와 구분하며,
  참조가 없는 정의는 각주 파트에 추가하지 않는다.
- 참조 노드에서 `w:footnoteReference` 런을 직접 만든다. 텍스트 요소 안에
  런을 끼워 넣던 구조를 없애고 파서의 ID로 정의와 연결한다. 각주 본문에는
  번호 표시용 `w:footnoteRef`도 넣는다.
- 각주 정의의 첫 문단만 추출하던 방식 대신 기존 블록 렌더러를 사용해 여러
  문단·목록·코드·표·수식·이미지를 처리한다. 일반 줄바꿈의 공백도 텍스트 런에
  넣는다. 각주 안의 추가 각주 참조는 라벨 텍스트로 보존한다.
- 각주 정의에 달린 메모는 본문 소스 위치에 빈 앵커로 남긴다. 각주 내용을
  렌더링할 때는 본문 메모를 소비하지 않아 파트 사이에서 참조가 섞이지 않는다.
- 각주 XML에 수식/그림 네임스페이스와 별도의 relationships 파트를 추가했다.
  본문과 각주가 자원 관계 생성 함수를 공유한다. 그림 ID 생성보다 관계 ID가
  하나 작았던 계산도 바로잡았다.
- 실제 생성 XML에서 각주 참조의 부모·정의 번호·다중 블록 내용·각주 링크
  관계·본문/각주 그림의 ZIP 엔트리 연결을 확인하는 회귀 테스트를 작성했다.
  긴 펜스 안의 짧은 펜스·코드 각주·정의 없는 참조·반복 참조도 포함한다.
  사용자 지침에 따라 테스트·타입 검사·빌드·앱 실행은 하지 않았다.
- 실제 Word에서 반복 각주 표시·복잡한 블록 레이아웃은 검증하지 않았다.
  인용 센티넬 방식과 이미지 캡션 문단 구조, 각주 제목의 앵커 할당 순서는
  아래 단계에서 보완했다. 실제 Word의 파트 간 이동 확인은 남아 있다.

### DOCX 그림과 캡션의 문단 구조 (2026-10-21)

- 인라인 렌더 결과를 런과 캡션 문단으로 분리했다. 이미지가 문장 중간이나
  하이퍼링크 안에 있어도 캡션은 포함 문단을 닫은 뒤 이미지 순서대로 출력한다.
  제목·서지·목록에서도 동일하며, 표 셀과 각주는 각 컨테이너 안에 유지한다.
- SVG 이미지는 `w:r/w:drawing`, Mermaid 블록은 `w:p/w:r/w:drawing`으로
  감싼다. 이미지가 문단 안에 새 문단을 만들거나 DrawingML이 런 없이 직접
  문단에 들어가던 구조를 제거했다. 도형 텍스트 상자 내부 문단은 유지한다.
- 이미지 설명은 중첩 강조·인라인 코드·줄바꿈을 포함해 텍스트로 수집한다.
  파일명 설명의 캡션 제외 규칙을 유지하며, 누락 이미지의 대체 설명도 보존한다.
  서지 문단을 두 번 렌더링해 미디어와 캡션 번호를 중복 소비하던 부분을 없앴다.
- 생성 XML의 그림 부모와 문단 부모, 문장 전후 텍스트, 링크 안 그림,
  연속 캡션 순서, 표 셀·각주 안 캡션, SVG·Mermaid 런, 서지 미디어 중복을
  확인하는 회귀 테스트를 작성했다. 사용자 지침에 따라 실행하지 않았다.
- Word의 실제 표시·페이지 배치·필드 번호 갱신은 검증하지 않았다.
  한 문단에 여러 그림이 있으면 캡션도 해당 문단 뒤에 모아서 출력한다.

### DOCX 그림 식별자와 로컬 이미지 URL (2026-10-21)

- 비트맵·SVG·Mermaid는 본문과 각주를 포함한 하나의 문서 카운터에서
  `wp:docPr` ID를 할당한다. SVG 변환기의 프로세스 전역 카운터를 제거하고
  호출자가 ID를 전달한다. 그림 종류별 번호 범위가 겹치던 가능성을 없앴다.
- 미디어 파일의 관계 번호는 등록 순서로 별도 할당한다. 전체 그림 번호에서
  미디어 개수를 빼서 추정하지 않으므로 SVG가 끼어 있거나 변환이 실패해도
  비트맵의 `r:embed`와 relationships 대상 파일이 어긋나지 않는다.
- `ImageSource::resolve_url`은 쿼리·조각 식별자를 분리한 뒤 공통 링크
  해석기로 percent-encoding을 한 번 복호한다. `%23`·`%3F`·`%25`는
  실제 파일명 문자로 유지하며, SVG 판별도 해석된 경로의 확장자로 한다.
  원격·data·file 등 스킴 URL과 `//host`는 로컬 파일로 읽지 않는다.
- 원시 파일 경로용 `resolve`는 그대로 유지해 이미 복호한 EPUB 경로가
  다시 복호되지 않게 했다. DOCX의 이미지 폭 조회는 원래 Markdown URL을 쓴다.
- URL 경로 사례, 본문·각주의 SVG/Mermaid/WebP 혼합, 변환 실패 뒤 ID,
  관계 대상 ZIP 파일의 실제 바이트를 확인하는 회귀 테스트 코드를 보완했다.
  사용자 지침에 따라 테스트·타입 검사·빌드·앱 실행은 하지 않았다.
- 원격 이미지 다운로드나 data URI 임베딩을 추가한 것은 아니다. 누락·미지원
  이미지의 기존 대체 텍스트 처리와 Word 실제 표시 검증 과제는 남아 있다.

### DOCX 목록 번호와 계속 문단 (2026-10-21)

- `DocxLists`는 Comrak의 각 List 노드에 독립적인 `w:num` 인스턴스를
  할당한다. 시작값(0 포함)을 해당 깊이의 `startOverride`에 기록하며,
  본문·중첩·각주의 별도 목록이 앞 목록의 번호를 이어받지 않게 한다.
- 번호 목록은 중첩해도 십진수를 유지하고 원문의 `.`·`)` 구분자를 반영한다.
  기존 번호 정의의 네임스페이스 없는 `lvl` 요소를 `w:lvl`로 교체했으며
  렌더러가 쓰는 0~8 깊이를 모두 정의한다. 그보다 깊은 목록은 8로 제한한다.
- 항목의 첫 문단에만 번호/글머리표를 붙인다. 계속 문단은 본문 시작 위치로
  들여쓰고 번호를 소비하지 않는다. 제목·코드 등으로 시작하거나 비어 있는
  항목은 별도 표식 문단을 만들어 목록 항목 자체가 사라지지 않게 한다.
- 순서 없는 작업 항목은 체크박스를 글머리표 대신 사용한다. 번호가 있는
  작업 항목은 부모 목록의 번호와 체크박스를 함께 보존하며, 계속 문단에는
  체크박스를 반복하지 않는다. 인용 안 목록의 인용 스타일도 유지한다.
- 번호 XML의 네임스페이스·9개 깊이·0 시작값, 실제 DOCX의 재시작·중첩·
  계속 문단·작업 항목·빈 항목·각주 목록 관계를 확인하는 회귀 테스트를 작성했다.
  사용자 지침에 따라 테스트·타입 검사·빌드·앱 실행은 하지 않았다.
- Word의 실제 번호 표시·페이지 배치는 미검증이다. 체크박스는 표시용 기호이며,
  목록 안 표·코드·제목 등 복잡한 블록의 들여쓰기와 한 줄 배치는 추가 과제다.

### DOCX 인용 구문 보호와 링크 구조 (2026-10-21)

- 완성된 XML의 센티넬을 하이퍼링크로 치환하던 경로를 제거했다. 알려진
  인용은 이스케이프한 표시 문자열과 내부 목적지를 갖는 Markdown 링크로
  만들고 기존 인라인 렌더러가 Word 하이퍼링크·위첨자 런을 생성한다.
  `w:t` 안에 하이퍼링크가 들어가거나 접미사의 특수문자가 이중 이스케이프되는
  문제를 없애고, 원문에 있던 사설 유니코드 문자는 그대로 둔다.
- Comrak으로 코드 펜스·들여쓴 코드·인라인 코드·이스케이프·기존 링크·이미지·
  수식·HTML 구간을 읽어 인용 변환에서 제외한다. 펜스 길이/종류를 단순 토글로
  추측하지 않는다. 서지 후보를 임시 마스킹할 때 UTF-8 바이트 위치를 유지한다.
- 정의가 없는 인용은 공백을 포함한 원문을 유지하고, 사용하지 않은 각주의
  인용은 번호를 소비하지 않는다. 전처리는 줄 수·끝 줄바꿈·정의의 들여쓰기를
  유지하며 서지 항목 내부의 강조·코드·이미지 처리는 기존 렌더러가 담당한다.
- 인접한 서지 정의가 한 문단에 합쳐져도 각 정의 위치에 북마크를 만든다.
  중복 키는 마지막 정의를 이동 대상으로 삼고, 앞 정의의 내용도 덮어쓰지 않는다.
- 생성 XML의 인용 부모·표시 텍스트·위첨자/굵게·목적지의 일대일 대응·각주,
  긴 펜스·코드·이스케이프·특수문자·중복 정의·미사용 각주의 회귀 테스트를
  작성했다. 사용자 지침에 따라 테스트·타입 검사·빌드·앱 실행은 하지 않았다.
- Word 실제 이동·표시는 미검증이다. 프런트 인용 파서와의 전체 의미 일치,
  인접 서지 항목을 각각 독립 문단으로 배치하는 개선은 남아 있다. 인용을
  포함한 제목의 원문 기준 앵커는 아래 단계에서 보완했다.

### 편집기 인용 분석 공유와 HTML 리터럴 보존 (2026-10-21)

- 프런트 `citeNumbering`은 Lezer 구문 범위를 사용해 코드 펜스의 종류/길이,
  들여쓴 코드·인라인 코드·이스케이프·링크·이미지·수식·HTML·위키링크와
  프런트매터를 인용에서 제외한다. 렌더러가 리터럴로 처리하는 하이라이트
  내부도 제외한다. 서지 후보 마스킹은 원문 UTF-16 길이와 CRLF를 유지한다.
- Lezer가 미해결 `[문자]`도 Link로 만드는 특성을 고려해 분석 전용 Citation
  노드를 추가했다. 단독 인용을 링크로 오인하지 않고, 인용 모양의 문자가
  있는 실제 링크·이미지도 바깥 구문 전체를 보호할 수 있다.

  Text 객체별 WeakMap 캐시를 유지하고 청크 범위를 이진 탐색한다. 검수 패널은
  같은 결과에서 끊긴 인용을 얻어 문서 전체를 다시 분석하지 않는다.
- HTML은 공통 분석에서 인정한 서지만 변환한다. 중복 키는 마지막 항목에만
  목적지 ID를 주고 앞 항목의 내용도 보존한다. 기존 링크 내부에는 인용 링크를
  만들지 않으며, 별도 인라인 파싱을 거치는 이미지 설명의 인용 토큰은 원문으로
  되돌려 대체 텍스트가 번호로 바뀌거나 빠지지 않게 한다.
- 구문 제외 범위·CRLF/이모지 오프셋·청크 경계·중복 정의·편집기 장식과

  인용·펜스 언어의 별도 후보 캐시와 적용 계약은 추가 개선 대상이다.

### 이모지 자동완성의 원문 교체와 별칭 검색 (2026-10-21)

- 자동완성 교체 범위에 시작 콜론을 포함한다. 별칭 중간에서 선택하면 남은 별칭과
  선택적 닫는 콜론을 함께 교체하고 이모지 문자만 넣는다. 주변 괄호·구두점·본문은
  보존하며 UTF-16 길이로 커서를 배치해 조합 이모지 뒤에 둔다. 삽입을 별도 실행
  취소 경계로 만들고 적용 직전 현재 문맥·검색어·읽기 전용을 다시 확인한다.
- 정규화한 이름·별칭은 미리 계산한다. 정확한 숏트이름, 정확한 별칭, 접두 일치,
  부분 일치 순으로 정렬하며 접두 일치를 다른 별칭의 부분 일치가 덮지 않는다.
  한글 분해형 입력도 NFC로 비교한다. 후보 상한은 검색·정렬 뒤에 적용한다.
- 직접 검색한 결과는 CodeMirror의 표시명 필터를 다시 거치지 않는다. 한글 별칭
  결과가 영문 표시명 때문에 사라지지 않으며 입력·삭제 시 전체 별칭 목록에서
  갱신해 좁혀진 후보를 복원한다. 콜론만 남으면 후보를 닫는다.
- 줄 시작·공백·여는 괄호/인용부호 뒤에서만 시작한다. 경로·이스케이프·중복
  콜론과 코드·메타데이터·수식·링크 구문은 침범하지 않는다. 기존 구문 트리를
  읽는 공통 가드를 위키·슬래시·이모지가 공유하며 입력마다 전문 파싱하지 않는다.
- 기존 후보 검사를 실제 삽입 결과 검사로 바꾸고 조합 이모지·기존 콜론·주변
  텍스트·실행 취소·Unicode 별칭·보호 문맥·잠금/필터 거절·오래된 결과·실제
  자동완성 엔진의 한글 검색 및 후보 복원 회귀 테스트를 추가했다. 사용자 지침에
  따라 테스트·타입 검사·린트·빌드·앱 실행은 하지 않았다.

### 인용 자동완성의 키 교체와 문서 분석 공유 (2026-10-21)

- 인용 자동완성을 별도 모듈로 분리하고 교체 범위에 `[@`를 포함한다. 키 중간에서
  선택하면 남은 키와 기존 닫는 괄호를 함께 교체해 괄호를 중복하지 않는다.
  쉼표 뒤 페이지 표기와 공백은 그대로 유지하며 아직 닫히지 않은 페이지 표기는
  열린 상태로 보존한다. 완성 적용은 한 번의 실행 취소로 되돌릴 수 있다.
- 후보에 서지 항목 설명을 표시하고 검색 뒤 20개 상한을 적용한다. 입력·삭제 때
  현재 정의 전체에서 다시 검색하므로 좁힌 결과를 복원하고 서지 변경도 반영한다.
  적용 직전 문맥·검색어·정의 존재 여부·읽기 전용 상태를 다시 확인한다.
- 서지 정의 줄, 페이지 표기 입력 위치, 코드·메타데이터·수식·위키 링크와 일반
  링크 내부에서는 키 완성을 제안하지 않는다. 편집기 구문상 shortcut Link로
  표시되는 독립된 `[@key]`는 기존 인용 수정 대상으로 허용한다. 문맥 판정은
  편집기의 기존 구문 트리를 사용하며 자동완성마다 강제 파싱하지 않는다.
- 미리보기·검수·자동완성이 불변 CodeMirror Text를 키로 한 WeakMap 분석을
  공유한다. 같은 문서에서 선택만 바뀌면 재사용하고 새 문서 버전은 처음 필요한
  시점에 한 번 전문 분석한다. 소비자는 분석 결과를 읽기 전용으로 사용한다.
- 괄호·페이지 표기·실행 취소·보호 문맥·오래된 결과·정의 갱신·실제 자동완성
  후보 복원과 문서 버전별 캐시의 회귀 테스트를 추가했다. 사용자 지침에 따라
  테스트·타입 검사·린트·빌드·앱 실행은 하지 않았으며 변경은 정적으로 검토했다.

### 코드 펜스 언어 선택과 원문 보존 (2026-10-21)

- 언어 후보를 별도 모듈로 분리하고 기존 구문 트리의 FencedCode 첫 CodeMark를
  기준으로 여는 줄을 판정한다. 세 글자보다 긴 펜스·들여쓰기·인용문·목록의
  코드 블록을 지원하며 닫는 펜스, 다른 코드 블록 속 예시, 프런트매터와 언어
  뒤 메타데이터 위치에서는 언어를 제안하지 않는다. 강제 구문 파싱은 하지 않는다.
- 이름·별칭 검색에서 정확한 일치를 우선하고 검색 후 30개 상한을 적용한다.
  표시명으로 재필터링하지 않아 `js` 후보가 `JavaScript` 표시 때문에 사라지지
  않는다. 입력·삭제마다 전체 목록에서 재검색하고 빈 언어 입력에서는 목록을
  복원한다. 자동완성 범위에 여는 펜스를 포함하되 실제 변경은 언어 토큰에 한정한다.
- 선택한 언어는 소문자 이름 또는 인식 가능한 단일 토큰 별칭으로 넣는다.
  `Common Lisp`처럼 공백이 있는 이름은 `lisp`로 넣어 Markdown 언어 판별과
  일치시킨다. 기존 토큰의 나머지 글자를 교체하고 펜스·공백·후속 속성은 유지한다.
  적용 직전 문맥·검색어·읽기 전용을 다시 확인하며 한 번의 실행 취소로 되돌린다.
- 실제 삽입과 실행 취소, 별칭 해석, 중첩 펜스·메타데이터 보호, 오래된 결과와
  잠금/필터 거절, 자동완성 엔진의 별칭 검색·후보 복원·상한 밖 언어 검색 테스트를
  추가했다. 기존 JavaScript 키워드 테스트는 정적으로 제공한 언어 지원을 사용해
  비동기 로딩 타이밍에 의존하지 않도록 바꿨다. 테스트·타입 검사·린트·빌드·앱
  실행은 사용자 지침에 따라 생략했다. 언어 데이터의 다중·배열·비동기 소스
  전달 방식은 별도 개선 대상으로 남아 있다.

### 기본 언어 자동완성과 Markdown 후보의 공존 (2026-10-21)

- `wikiAutocompletion`은 자체 Markdown 소스를 EditorState 언어 데이터에
  추가한다. 전체 소스를 override로 대체한 뒤 첫 결과만 반환하던 중계 함수를
  제거했다. JavaScript의 키워드와 지역 변수처럼 별도로 제공되는 후보를 기본
  엔진이 함께 처리하며 배열 형식의 후보와 비동기 소스도 기본 계약을 따른다.
- 자체 매처는 위키·슬래시·인용·태그·펜스 언어·이모지만 처리하고 언어 데이터
  소스를 재호출하지 않는다. 소스 간 결과를 하나로 합치지 않아 각 소스의 교체
  범위·필터·갱신·스니펫·취소 문맥을 유지한다. 느린 결과를 기다리는 동안 빠른

  문서가 잠긴 뒤에는 인용·위키 같은 자체 소스와 동일하게 변경하지 못한다.
- 위키·펜스의 자동완성 엔진 테스트를 실제 앱 확장 구성으로 변경했다. 키워드와
  지역 변수의 동시 표시, 배열·비동기 후보, 스니펫 필드 이동, 서로 다른 교체 범위, 커서 이동 취소,
  잠금 후 적용 거절의 통합 테스트를 추가했다. 사용자 지침에 따라 테스트·타입
  검사·린트·빌드·앱 실행은 하지 않고 소스와 변경 내용을 정적으로 검토했다.

### 문서 찾기·바꾸기의 검색 상태와 변경 계획 (2026-10-21)

- 검색 예약은 현재 탭·쿼리·열림 상태에 묶는다. Enter와 이동 버튼은 예약을
  취소만 하지 않고 현재 검색을 즉시 적용한다. 빈 검색어·잘못된 정규식·닫힘·탭
  전환은 이전 예약을 취소하며, 같은 EditorView를 재사용해도 활성 탭 ID가
  바뀌면 새 문서에 검색을 적용한다. 비어 있는 검색어도 설정에 저장한다.
- 원문을 소문자로 변환한 뒤 그 좌표를 쓰던 검색을 공통 매처로 교체했다.
  Unicode 정규식으로 원문의 UTF-16 범위를 유지해 İ 같은 글자 뒤의 위치가
  어긋나지 않는다. 단어 단위는 문자·숫자·결합 문자·밑줄을 기준으로 한글도
  구분한다. 정규식은 Unicode 및 줄 단위 앵커를 지원하며 검증과 실행이 같은
  문법을 사용한다. 빈 일치는 코드 포인트 단위로 진행하고 빈 장식을 만들지 않는다.
- 일반 문자열 편집은 영향받지 않은 앞쪽 결과를 보존한 뒤 알려진 일치 경계부터
  뒤쪽을 재검색한다. 고정된 작은 창으로는 처리할 수 없는 연속 중첩 패턴의
  비중첩 결과 이동과 표시 상한 밖 결과 보충을 처리한다. 정규식·단어 단위는
  전문을 재검색한다. 문서와 검색 조건이 함께 바뀌어도 좌표를 두 번 옮기지 않는다.
- 이전/다음 이동은 현재 선택한 일치와 방향을 기준으로 순환해 인접 매치를
  건너뛰거나 이전 이동이 항상 첫 결과로 향하지 않는다. 정규식 바꾸기는 캡처
  그룹·이름 그룹·전체 일치·달러·앞뒤 원문 치환을 지원하고 일반 바꾸기는 입력을
  그대로 넣는다. 각각의 적용은 별도 실행 취소 경계로 묶는다.
- 한 번에 최대 5,000건을 표시하고 추가 결과가 있음을 안내한다. 다음·이전은
  필요한 결과 구간을 불러와 문서 전체를 탐색한다(뒤의 검색 표시 구간 절 참고).
  모두 바꾸기는 표시 상한과 별개로 전체 변경 계획과 실제 건수를 먼저 만든다.
  확인 후에는 탭·문서 객체·검색 조건·대체 문자열·읽기 전용 상태가 동일한지
  확인한다. 중복 제출을 막고 필터 거절·확인창 실패·대상 변경 때 성공을 알리지
  않으며 입력을 유지한다. 상태 안내·입력 이름·오류 알림과 좁은 창의 줄바꿈도 보완했다.
- 유니코드 위치·한글 경계·빈 정규식·중첩 패턴·상한 보충·전체 바꾸기·실행 취소·
  캡처 치환과 패널의 Enter/IME·예약 취소·탭 전환·확인 중 변경·실패 복구 테스트를
  추가했다. 사용자 지침에 따라 테스트·타입 검사·린트·빌드·앱 실행은 하지 않았다.
  뒤의 백그라운드 검색 절에서 정규식과 큰 문서의 계산을 별도 작업자로 옮긴다.

### 백그라운드 문서 검색과 강제 취소 (2026-10-21)

- 정규식, 200,000 UTF-16 단위를 넘는 문서, 2,000 단위를 넘는 검색어는 상태
  필드에서 직접 실행하지 않는다. 필드는 결과를 비우고 대기 상태·문서 버전을
  기록하며 ViewPlugin이 60ms 뒤 번들에 포함된 module Worker로 계산을 보낸다.
  작은 일반 문자열 검색은 기존 즉시 계산과 앞쪽 결과 재사용 경로를 유지한다.
- 편집기마다 지연 생성하는 작업자 하나와 실행 중 요청 하나만 둔다. 완료한
  작업자는 재사용하고 검색 변경·본문 편집·닫기·탭의 setState·편집기 해제는
  진행 중 작업자를 종료한다. 정규식 실행이 메시지나 AbortSignal을 처리하지
  못하는 경우도 terminate로 끊는다. 찾기는 2초, 바꾸기 계획은 5초 제한이다.
- 응답은 요청 ID, 작업자 인스턴스, 편집기 작업 세대, 문서 객체, 검색 버전을
  확인한 뒤 적용한다. 입력 중 요청한 결과 이동은 완료 뒤 수행하되 사용자가
  커서를 옮겼다면 이동을 취소한다. 패널은 검색 상태 변경을 구독해 문서 편집이
  없는 완료·실패도 표시하며 시간 초과 뒤 Enter로 같은 검색을 다시 요청할 수 있다.
- 단일·전체 바꾸기는 비동기 API로 변경했다. 정규식·큰 문서·대체 문자열로
  작업량이 커지는 경우 계획도 같은 작업자에서 계산한다. 적용 전 원문·조건·잠금·
  단일 바꾸기의 선택과 탭 소유권을 재확인한다. 계획이 생성할 문자열이 32,000,000
  UTF-16 단위를 초과하거나 변경이 500,000건을 초과하면 전체 계획을 거절하며
  일부만 적용하지 않는다. 문서 문자열 복사와 최종 원자적 트랜잭션은 여전히 UI
  스레드에서 수행하므로 이 변경이 모든 대용량 작업 비용을 없애는 것은 아니다.
- Worker를 만들지 못하거나 통신·실행에 실패하면 결과 없음과 구분해 안내한다.
  무거운 검색을 UI 스레드로 되돌리는 대체 실행은 없다. 작업자는 같은 출처의
  번들 파일을 사용하며 기존 CSP를 완화하지 않는다.

  수정하지 않았던 문서도 미저장 상태로 표시하고 열린 본문을 즉시 복구 초안에

  유지한다. 이미 맨 앞인 폴더의 반복 기록과 없는 항목 제거는 순번을 바꾸지
  않는다. 내용과 순번은 한 트랜잭션으로 저장해 실패 시 이전 목록을 유지한다.
- `openWorkspace`는 폴더 조회가 성공했고 해당 열기 요청이 아직 현재 요청일
  때만 기록한다. 느린 이전 스캔이 최신 폴더의 순서를 바꾸지 않으며 기록 큐를
  기다리는 사이에 바뀐 열기 요청도 제외한다. 기록 저장 실패는 폴더 열기
  실패로 취급하지 않고 별도 목록 오류로 표시한다.
- `WorkspaceHistory`는 편집기와 별도 구독을 가진다. 변경 이벤트를 먼저 구독한
  뒤 목록을 읽고 서버 순번과 요청 세대로 오래된 조회·오류 응답을 무시한다.
  기록·제거·비우기는 직렬 처리하며 저장 전 표시 목록을 미리 변경하지 않는다.
- 연결이 끊기거나 사라진 폴더도 자동 제거하지 않아 다시 시도하거나 다른
  폴더로 전환할 수 있다. 제거·비우기는 목록만 변경하고 파일이나 현재 작업
  폴더는 건드리지 않는다. 제거 뒤에는 이웃 항목으로 포커스를 옮기되 사용자가
  다른 입력창으로 이동했으면 포커스를 가져오지 않는다.
- 재시작 보존, 목록 상한·순서·멱등성, 저장 실패 롤백, 늦은 조회·기록 큐,
  성공한 최신 폴더만 기록, 미저장 문서 보존, 동명 폴더·한글 검색·포커스·
  명령 팔레트 연결의 회귀 테스트를 작성했다. 사용자 지침에 따라 실행 검증은
  하지 않고 소스와 변경 내용을 검토했다.

### 닫은 탭 복원과 닫기 확인 통합 (2026-10-21)

- 명령 팔레트의 탭 닫기도 App의 `closeTabWithConfirm`을 거친다. 스타일 저장,
  미저장 내용 확인, 확인 이후 변경 감지, 취소 시 초안 보존을 다른 닫기 경로와
  공유하며 팔레트에서 `store.closeTab`을 직접 호출하지 않는다.
- `AppStore`는 창별 최근 20개 저장 파일의 경로·보기 모드·잠금·탭 순서·선택·
  스크롤만 메모리에 보관한다. 같은 경로는 최신 기록 하나만 남긴다. 본문이나
  실행 취소 기록을 보관하지 않으며, 이름 없는 문서와 폐기한 수정은 복원하지
  않는다. 앱을 다시 시작하면 닫은 탭 기록은 초기화된다.
- 탭 막대·파일 메뉴·명령 팔레트·Shift+Cmd/Ctrl+T가 같은 복원 동작을 사용한다.
  다시 열 때 기존 파일 열기의 중복 요청 처리와 최신 이동 요청 확인을 공유한다.
  디스크의 최신 본문을 읽고 선택을 파일 길이에 맞게 제한한다. 저장 시각과
  문자 수가 일치하면 기존 스크롤도 복원한다. 이미 열린 파일은 미저장 내용과
  선택을 유지한 채 활성화한다.
- 읽는 동안 편집·선택·탭 이동이 발생하면 활성 문서와 위치를 바꾸지 않는다.
  중복 복원 요청은 무시하며, 실패한 읽기는 재시도할 수 있게 기록을 유지한다.
  성공하면 해당 기록만 제거하므로 읽는 중 새로 닫은 탭의 기록은 남는다.
- 최신 본문·폐기 처리, 선택·읽기 위치·잠금, 순서와 상한, 실패 후 재시도,
  늦은 읽기와 중복 실행, 팔레트의 닫기 확인 위임, 빈 탭 막대와 단축키 가드의
  회귀 테스트를 작성했다. 테스트·타입 검사·린트·빌드는 실행하지 않았다.

### 인쇄·소스 미리보기와 PDF 출력 일치 (2026-10-21)

- `captureExportSnapshot`은 본문 외에 프런트매터를 보존한 `markdown`과 언어도
  캡처한다. 위키링크 변환은 본문에만 적용한다. HTML·PDF 조립에는 이 원문을
  전달해 `columns` 정보가 본문 추출 과정에서 사라지지 않도록 했다.
- `snapshotHtmlOptions`를 인쇄 미리보기와 PDF 내보내기가 공유한다. 서식·이미지와
  표 폭·목차·머리글·바닥글·쪽번호·언어가 같은 스냅샷에서 나온다. 이전 PDF
  경로에서 빠졌던 쪽번호 생성 및 목차 옵션을 연결했다. 최종 HTML에는 언어와
  브라우저 인쇄용 용지·방향 CSS를 명시한다.
- 인쇄 미리보기는 용지 방향 설정을 복원하고 선택한 용지 폭으로 프레임을
  표시한다. 화면은 연속 본문 미리보기이며 실제 페이지 분할·반복 머리글·쪽번호는
  PDF 생성 단계에서 처리한다는 점을 안내한다. PDF 버튼은 확인한 HTML까지
  전달하므로 저장 대화상자 이후 본문·스타일·로컬 이미지 변경이 출력에 섞이지
  않고 무거운 본문 렌더도 반복하지 않는다.
- 미리보기는 문서·옵션 요청의 정체성을 추적한다. 옵션 변경은 디바운스하며
  이전 문서의 성공·실패 응답을 무시한다. 최종 프레임과 글꼴 준비 전에는
  인쇄·PDF 버튼을 잠그고 렌더 실패는 옵션을 유지한 재시도를 제공한다.
- 전역 본문 캐시와 프레임 참조를 없앴다. 각 패널은 본문 하나만 재사용하며
  테마·위키 해석·문서 정보가 달라지면 갱신한다. 미리보기를 다시 열면 로컬
  이미지도 다시 읽는다. 소스 미리보기 역시 오류·재시도를 제공한다.
- 인쇄 프레임은 스크립트를 허용하지 않고 인쇄 대화상자 권한만 추가했다.
  Tab·Escape를 부모 모달로 전달하고 외부 링크 이동을 막는다. 스크롤은 해당
  미리보기 안에서 보존하며 문서 전환 시 초기화한다. 프레임 교체·닫기에서
  이벤트와 늦은 글꼴 완료 콜백을 정리한다.
- 옵션 전달·본문 재사용·실패 재시도, 최신 요청 우선, 프레임 준비 상태,
  PDF 스냅샷 전달, 테마 변경, 키보드·폰트 대기·최종 HTML의 회귀 테스트를
  작성했다. 사용자 지침에 따라 실행 검증은 하지 않고 소스만 검토했다.

### 내보내기 취소·실패·완료 흐름 (2026-10-21)

- `runExport`는 저장 완료 경로, 위치 선택 취소, 실패 메시지를 구분한
  `ExportResult`를 반환한다. 실행 직후 옵션 창을 닫지 않으므로 저장 취소나
  쓰기 실패 뒤에도 용지·방향·여백·배율을 유지하고 다른 저장 위치로 재시도할
  수 있다. 완료 뒤에는 실제 경로를 표시하고 사용자가 창을 닫는다.
- 옵션 창은 열릴 때 원본 문서·경로·서식·언어·메모를 캡처하고 문서 이름과
  캡처 시점 안내를 보여 준다. 이후 활성 탭이나 문서가 바뀌어도 같은 내용으로
  재시도한다. 페이지 번호·머리글은 사용자가 현재 선택한 값을 적용한다.
  인쇄 미리보기의 PDF 내보내기도 준비된 HTML과 옵션을 유지한다.
- `useExportTask`는 React 렌더 이전에 실행을 잠가 연속 클릭을 합치고 완료한
  작업의 중복 저장을 막는다. 처리 중 Escape·배경 클릭·취소 버튼은 창을 닫지
  않는다. App의 Escape 안전망과 종료 가드도 이 상태를 따른다. 해제된 패널의
  늦은 결과는 다른 화면을 갱신하지 않는다.
- `ExportFeedback`은 취소·실패·완료를 같은 방식으로 안내하고, 저장 성공 뒤
  Finder에서 실제 결과 파일을 표시한다. Finder 호출 실패는 저장 실패와
  구분하며 경로와 완료 상태를 유지한 채 위치 표시만 다시 시도할 수 있다.
- 내보내기 중에는 창 안의 진행 표시를 사용하고 일반 작업 오버레이를 중복해서
  띄우지 않는다. 외부 파일 변경 충돌 창은 내보내기 창을 닫은 뒤 확인하도록
  미룬다. 다른 명령과 종료는 기존 모달·작업 가드로 보호한다.
- 취소·실패 후 옵션과 원문 보존, 중복 실행·Escape 차단, 완료 경로, Finder
  실패 분리, 패널 해제 뒤 응답, 인쇄 미리보기의 HTML 재사용과 재시도 테스트를
  작성했다. 사용자 지침에 따라 테스트·타입 검사·린트·빌드는 실행하지 않았다.
